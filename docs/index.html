Meet Lim

Lim is an experimental, compiled Lisp with explicit, strong static types. It is meant for code that people and machines can both read. You can write it by hand, ask a language model to produce it, or generate it from other code. In each case, you should be able to open the result and follow what it does. This page explains the design, walks through examples, and keeps the full reference close at hand.

Read what runs

Explicitness is the guiding principle. Declarations and behavior are written out in source. Local variable declarations include a type instead of asking the compiler to infer one. A function returns through an explicit return statement; its final expression never silently becomes its return value. Arithmetic operations state the types they operate on and, where relevant, how overflow is handled. Ordinary function calls name their arguments, so you can see which parameter receives each value at the call site. Builtin operations and special forms can also have positional operands.

Note: the # prefix is reserved for language keywords, builtin types and operators, such as #fn, #u64 and #return. User declarations cannot use that prefix. Adding a future builtin #feature therefore leaves your feature name available; this does not promise that every future language change is backward-compatible.

A small surface notation makes handwritten code lighter: records, indentation, colon grouping and infix expressions reduce parentheses, verbosity and visual noise. This syntax sugar lowers to the same explicit parenthesized trees that code generators manipulate.

#fn add {
  #params = { left = #u64; right = #u64; };
  #returns = #u64;
  #body: #return [#u64 #wrap; left + right];
}

#fn main {
  #params = {};
  #returns = #u64;
  #body: #return add { left = 40; right = 2; };
}

The result is the process exit status, 42. Braces contain named pairs; the colon groups the rest of its line; brackets contain typed infix arithmetic. The tutorial develops these rules step by step.

Generate concrete code at compile time

Code generation is built into Lim. Pure compile-time generators produce concrete, specialized types and their APIs: an optional value for a particular element type, a fixed array with bounds contracts, or a task state machine. This supports complex designs without hiding their implementation behind runtime dispatch. The generated Lim source is available to inspect, search and debug. The generator tutorial starts with a small example; the reference describes the restricted generator language and its contracts.

Follow a name to its definition

A direct file reference names both a source file and a declaration. An explicit alias gives that exact declaration a shorter file-local spelling:

// Two ways to name the same function in math.lim:
(#alias add = ./math.lim::add)
(#fn answer () #u64
  (#let first #u64 (./math.lim::add { left = 20; right = 22; }))
  (#return (add { left = first; right = 0; })))

The declaration's identity is its canonical file plus declaration name. Aliases change the spelling you use, not the identity, signature or ownership rules. This gives text search and editor go-to-definition a direct route to the source. There is no nested namespace lookup, chain of implicit imports or receiver-based method dispatch to unravel. A family spelling such as VecU64::sort is a single declaration name; :: within that name does not introduce a namespace. See direct references and aliases for path resolution and visibility rules.

Why a new language?

Lim is an intermediate representation you can read and audit. A generator or language model can produce it, and you can open the result and follow what it does: the types, named calls, ownership operations, and generated implementations are available in source. That makes inspection practical; it is not a formal security guarantee.

Generated programs still need human review. Following a call becomes harder when its meaning depends on implicit conversions, receiver lookup, hidden cleanup, or distant generic instantiations. Lim explores a deliberately smaller design: make those decisions visible, give generators a simple tree to produce, and check ownership and API requirements before emitting code.

Lim also avoids hidden call indirection. Function-pointer values, recursive calls, and implicit or virtual dispatch are unavailable. Generators can produce explicit branches, state machines and direct calls, and you can inspect that emitted Lim source. The generated code still has to obey the same rules; code generation does not permit recursion or indirect calls. References and raw pointers exist: this restriction concerns how function call targets are chosen.

For example, distributed enums collect a closed set of contributed variants at compile time. Fixed executors take an explicit list of tasks and emit direct calls. These building blocks allow runtime selection through visible generated branches with targets known for that build. See collections and cooperative tasks for their current scope and examples.

The goal is to shorten the path from an idea to code you can understand and run. The name evokes a limit as time approaches zero: less waiting to build, less overhead to execute, less time reconstructing intent. These are engineering targets, not benchmark results or a claim that Lim replaces established languages for every project. Lim is experimental and unreleased; syntax, semantics, backend coverage, and tooling can still change.

Keep testing and performance practical

Testability is part of the design. Explicit inputs, control flow and cleanup make it easier to isolate a behavior, write a test for it, and understand a failure. Contract audits can check whether a function's promises hold on the paths your tests exercise. Generated implementations can be inspected and tested as ordinary Lim code.

Very fast compilation is a first-class engineering goal, alongside excellent execution performance. Lim aims to produce efficient, predictable native machine code and minimize the work needed to build it. Cached generation, concrete implementations, and the internal encoder and linker support that direction. These choices do not establish a speed advantage or guarantee optimal assembly. The performance baseline and benchmark harness distinguish measured results from goals; representative workloads should guide optimization.

Why these design choices?

Choice Reason and tradeoff
One canonical tree, a small surface notation Generators work with whole structures; readers can use records, indentation and infix expressions. Sugar lowers to the same forms instead of defining a second execution model.
Explicit types and operations Bindings and arithmetic expose their meaning locally. There is no general type inference; unsuffixed literals can use an explicitly declared contextual type. This costs some extra source text.
Free-standing functions and explicit names Work::poll is a function name; Choice.Ready is an enum variant. There are no methods, traits, closures, function pointers or recursive calls to resolve. This restricts familiar abstractions.
Concrete generated definitions Pure compile-time generators produce ordinary Lim types and functions instead of user-facing generic types. Cached output in .lim is inspectable source with invocation provenance; concrete code can increase output size.
Reserved # builtins Language additions such as #feature avoid taking the user name feature. The prefix protects names, not every possible syntax or semantic change.
Native compilation The dependency-free Rust compiler encodes and links x86-64 Linux ELF executables internally. AArch64 and browser WebAssembly backends currently support smaller subsets.

What the compiler checks

Ownership and borrowing checks track moves, exclusive access, returned references and retained loans across functions, without user-written lifetime annotations. Linear values need explicit consumption; destruction is visible rather than silently inserted. Raw pointers and unsafe operations have an explicit boundary and still need an audit. These checks target specific classes of mistakes; they do not establish that every program is correct.

State API conditions without multiplying types

Often an API needs an ordinary value under a particular condition. One function might accept a #u64 only when it is positive; another might need that same type under a limit. Predicate contracts express those conditions without inventing a separate type for each one.

#requires says which exact evidence a caller must have. A #if-valid branch runs a predicate and supplies that fact in its successful branch. #ensures states facts subsequent code may rely on after a call; #preserves keeps a specified fact when the caller already had it, without requiring that fact to be supplied. Mutations can invalidate evidence about changed storage, so an earlier validation is not permission to use a later, altered value.

The checker tracks explicit predicate evidence across these boundaries; it does not search for theorems. The truth of #ensures and #preserves remains a programmer promise. --check-contracts audits those promises on exercised paths, which helps test an API without turning tests into mathematical proofs. #assume is a separate, explicit trust point: it accepts a claim without running the predicate. See the contract tutorial and verification notes.

Tutorial

Lim is a statically typed Lisp with explicit returns, ownership and arithmetic behavior. A small surface reader turns records, infix expressions and indentation into the same trees that code generators manipulate. Builtins begin with #; your names do not.

Start here, then use the complete language reference, alphabetical builtin table, or contract reference. The separate browser playground runs small examples with the real compiler. The full native language is broader than its first WebAssembly backend.

1. Return a value

This entire program returns 42:

#fn main {
  #params = {};
  #returns = #u64;
  #body: #return 42;
}

#fn declares a function. #params is a record of parameter names and types; this function has none. #returns is always explicit. #body contains the function’s forms. #u64 is an unsigned 64-bit integer. An unsuffixed literal gets its type from this explicitly declared context; 42u64 spells it directly.

For a function that returns no value, use #returns = (); and #return ();. Empty #requires, #ensures and #preserves fields may be omitted.

Run this natively from a checkout:

nix develop
cargo build
./target/debug/lim example.lim -o /tmp/example
/tmp/example
echo $?  # 42: the program's exit status, not printed output

The playground displays the returned value directly. Native exit statuses are limited by the operating system; returning a number is different from printing.

2. Read the tree beneath the sugar

Each surface form has a local, mechanical interpretation:

Surface spelling Tree or meaning
{ left = x; right = y; } ((left x) (right y))
(a : b c) (a (b c))
(a : b : c) (a (b (c)))
: a b (a b)
(: a b) ((a b))
#return x; #return y; inside a sequence Two complete forms, each grouped by its semicolon
A colon at the end of a line Group the following indented syntax; close on dedent
[#u64 #wrap; x + y * z] (#u64::add-wrap x (#u64::mul-wrap y z))
// comment A line comment

Inline colons consume through a newline, semicolon, or enclosing closing delimiter. Consecutive colons nest to the right. Semicolons inside explicit parentheses or an indented group belong to that group. Use spaces for layout.

Curly braces contain only key = value; entries, with key: available when the value is colon-grouped. Parentheses delimit ordinary forms; square brackets select infix parsing. Nested square brackets inherit their arithmetic header only through direct bracket nesting. A function-call parenthesis ends that inheritance, so brackets inside the call need their own header.

Canonical S-expressions remain useful for generators and fully explicit code:

(#fn main () #u64
  (#return (#u64::add-wrap 40u64 2u64)))

3. Declare and call a function

Calls name their arguments. Their written order can differ from the declaration; expressions are evaluated once in the order you write them. Names choose the destination parameters; they do not rearrange effects. An earlier argument finishes before a later one starts, and all arguments finish before callee entry.

#fn subtract {
  #params = { left = #u64; right = #u64; };
  #returns = #u64;
  #body: #return [#u64 #wrap; left - right];
}

#fn main {
  #params = {};
  #returns = #u64;
  #body: #return subtract { right = 2; left = 44; };
}

#wrap states overflow behavior. Integer arithmetic must choose the required wrapping or saturation behavior explicitly; comparisons use a type header without an arithmetic mode, such as [#u64; value < 100].

#call remains a canonical form understood by the compiler and generators. Handwritten code can call an ordinary function with its name and an argument record. Functions are free-standing declarations; there is no method lookup.

4. Mutate a local and write a loop

#let binds an immutable value. #let-mut permits assignment with #set. A range is half-open: 1 through 11 means the numbers 1 through 10.

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut total #u64 0;
    #for-range (number #u64) 1 11:
      #set total [#u64 #wrap; total + number];
    #return total;
}

The loop’s colon opens its body. Dedent closes it; the final return belongs to the function. #while, #for and #loop cover other iteration shapes. #break exits a loop; #continue starts its next iteration. In a #for loop, continuing still executes the step. Names cannot shadow existing bindings.

For actual printed output, see the working 1-through-10 native printing example. The browser’s initial scalar backend reports return values instead of host I/O.

5. Validate an API argument once

A predicate is an ordinary pure Boolean function. A function that requires it can be called only where the checker already has matching evidence.

#fn positive {
  #params = { value = #u64; };
  #returns = #bool;
  #body: #return [#u64; value > 0];
}

#fn accept {
  #params = { value = #u64; };
  #returns = #u64;
  #requires: positive { value = value; };
  #ensures: positive { value = (#result); };
  #body: #return value;
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let input #u64 42;
    #return (#if-valid positive { value = input; }
      accept { value = input; }
      0u64);
}

#if-valid runs the predicate. Its successful branch carries the evidence into the call. Ordinary #if does not grant this evidence. Removing the validation branch makes the call fail to check, even though this particular literal is 42. The checker follows explicit claims; it does not unfold predicates or solve arithmetic implications.

Mechanism What it gives you
#requires Evidence the caller must provide; available on function entry. Multiple clauses mean AND.
#ensures A programmer promise available after normal return. Instrumented builds audit it.
#preserves If the caller already had the property, it survives the call; it is not a prerequisite.
#result The returned value, available in a postcondition.
#old An entry observation for a postcondition; use scalar observations.
#assume Explicitly trust a claim without evaluating its predicate or arguments.
#where A fixed storage constraint with the base type’s representation.

Use --check-contracts when testing native programs. It audits requirements, postconditions and preservation, but does not prove a programmer’s promise for all inputs. Production can omit these extra audits. The playground enables them.

6. Borrow storage explicitly

A mutable reference grants exclusive access. End it before using the owner again:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut number #u64 40u64;
    #let view (#ref-mut #u64): #borrow-mut number;
    #deref-set view 42u64;
    #forget view;
    #return number;
}

#forget explicitly consumes this handle. Ownership and borrow checking remain active inside #unsafe. Linear values must be consumed; Copy values may be reused. Destruction is explicit. Returned references retain the source storage’s lifetime obligations.

Evidence is tied to the storage read by a predicate. A relevant write can revoke a temporary fact. Fixed constraints in stored types must instead be restored before an exclusive borrow returns access to the owner. See constrained types for the detailed restoration rules. A valid property of an unrelated field can remain available.

This example can use Check only in the browser; reference code generation currently belongs to the native backend.

7. Prove an array index

This checks the exact comparison needed by the access, then uses its evidence:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let items (#array #u64 2): #array-of (#array #u64 2) 20u64 42u64;
    #let view (#ref (#array #u64 2)): #borrow items;
    #let index #usize 1usize;
    #return: #if-valid [#usize; index < 2usize] (#index-proven view index) 0u64;
}

The index must be #usize, and the comparison must mention this index and this array length. A fact about another index or bound does not match. A named validator with the same implementation is still a distinct predicate.

To connect claims, call an ordinary helper with explicit #requires and #ensures. The generated fixed-array API supplies such a helper. The checker does not discover the conversion on its own. Proven access omits the bounds check in production; instrumented compilation audits the access. This example is available through Check only in the browser.

8. Generate a concrete type

Generators produce concrete declarations instead of hidden runtime dispatch:

#generate #optional { type = #u64; name = MaybeNumber; }

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let value MaybeNumber: MaybeNumber::construct { value = 42u64; };
    #return: #match value (#case (MaybeNumber.Some number) number) (#case MaybeNumber.None 0u64);
}

Generated source is inspectable in .lim/generated/. Builtin and library generators use reserved names such as #optional; user generators use ordinary names. The pure generator language uses #gn, #gn-fn and the restricted #gn-* operations. All emitted runtime code still passes ordinary validation.

Use the generator reference for syntax bundles, quoting, generated declarations, validation witnesses and file authority. Generating a type does not make it an opaque mathematical proof.

9. Follow a diagnostic

The compiler distinguishes parsing, generation, types, borrows, linearity, unsafe use, contracts, code generation and linking. A failed check gives a source location and, where available, related locations.

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let answer #u64 false;
    #return answer;
}

Here the declared type is #u64 and the value is #bool. Change false to 42. For contract errors, first compare the required predicate and argument identities with the available evidence. For borrow errors, inspect which owner or reference still has access. For unsupported WebAssembly code generation, use Check only or run the example natively.

10. Keep the compiler stages in view

Surface syntax changes how a tree is written. Generators change which concrete program is checked. Type, ownership, borrow and contract checking decide whether that program is accepted. A backend then emits code for its supported operations. An unsupported backend feature is an error, not permission to skip validation.

Language reference

Lim code fences carry explicit test metadata: run=N compiles and runs with exit code N; library compiles through native emission; fragment=NAME uses the named function wrapper in tests/language_docs.rs; error=CODE must fail with that diagnostic. syntax marks schematic forms or signatures with intentionally undefined placeholders; these are parsed, not type-checked. The documentation tests cover this reference, README, allocator notes, and the soundness audit, and reject unclassified Lim fences.

Lim is a compiled, statically typed Lisp. Its syntax is made of S-expressions, but its type and evaluation rules are deliberately explicit. The compiler currently targets Linux x86-64 System V. It emits inspectable assembly, then encodes and links ELF binaries internally, including supported ELF objects and shared-library calls. Unsupported assembly or object features produce a link diagnostic; the compiler does not invoke as or ld.

This document describes the language implemented by this crate. Builtin forms and all sixteen scalar types use a leading #, such as #u64 or #bool; unprefixed builtin forms and scalar types are rejected. Numeric literal suffixes keep their established spelling, such as 42u64. User-defined type names remain ordinary identifiers and never receive a # prefix.

Declaration spelling identifies its role. Every :: component in a type name starts with an ASCII uppercase letter (Reading, Work::Frame). Functions, parameters, fields and variables start lowercase or with _; a function can have uppercase type prefixes (Work::poll). A dot is reserved for enum variants: Work::Poll.Ready is variant Ready of enum Work::Poll. These are single global identifiers, not namespace or field-access operations. The compiler enforces the same rules on generated declarations and handwritten code. Compiler-issued hygienic #gn-gensym names occupy a separate reserved domain; they can also name private types without colliding with public declarations.

User function names retain their identity in named calls, even when a name also spells a builtin. For example, panic { value = reference; } calls the declared user function named panic; (#panic) remains the builtin trap. Calls require named arguments, evaluate their expressions in written call-site order, and apply the declared function signature and ordinary eager-call ownership rules. Ordinary calls accept only safe functions, even inside #unsafe. Use #unsafe-call for unsafe or external functions; it requires an enclosing #unsafe block and uses the same named arguments, evaluation order, signature checks, and ownership rules.

Strict scalar intrinsics also accept ordinary named calls. The compiler generates their typed signatures and lowers calls to the existing native operations. Binary parameters are left and right; unary not takes value. Integer arithmetic still requires -wrap or -saturate. Short-circuit #bool::and and #bool::or retain their direct control-flow forms. Callable subtraction is binary; direct subtraction also supports unary negation. Floating-point remainder is currently unsupported by the native backend and has no callable declaration.

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let index #usize 1usize;
    #return:
      #if-valid
        (#usize::lt { left = index; right = 4usize; })
        (#u64::add-wrap { right = 22u64; left = 20u64; })
        0u64
}

For syntax, contextual examples, and semantics of every builtin, see the alphabetical builtin reference and its typed operator families.

Design and scope

Surface notation

Surface forms lower to the same explicit S-expression representation used by generators and the checker. Canonical parenthesized forms remain supported. The executable surface example combines generated arrays, contracts, infix expressions and local indentation lists.

#fn increment {
  #params = { value = #u64; };
  #returns = #u64;
  #requires:
    [#u64; value < 99];
  #ensures:
    [#u64; (#result) < 100];
  #body:
    #return [#u64 #wrap; value + 1];
}
#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let input #u64 41;
    #return (#if-valid [#u64; input < 99]
      (increment { value = input; })
      0u64);
}
  • { key = form; ... } is a named pair list. Keys are literal identifiers; inline values are single forms and require a final semicolon. Indented list values use key: as described below. Empty records use {}. Duplicate argument keys are checked by their consumer.
  • function { name = value; } and (function { name = value; }) are ordinary named calls, including generated scalar intrinsics. function ((name value)) and (function ((name value))) are equivalent. Empty calls use function {} or (function ()). No #call marker is required. They use the same safe call checks and written-order evaluation as #call. Unsafe calls retain #unsafe-call and an enclosing #unsafe.
  • In a parenthesized semicolon list, #let x #u64 expression; #return x; groups into two forms. Existing parenthesized forms are retained. A nested call and its argument record constitute one expression. Every group needs a terminating semicolon; newlines alone do not terminate forms.
  • [#u64 #wrap; a + b * c] scopes the scalar operator type and integer overflow mode. Integer arithmetic requires #wrap or #saturate; comparisons and floating arithmetic omit the mode. Operators have fixed precedence: unary, multiplication/division/remainder, addition/subtraction, shifts, bitwise AND/XOR/OR, comparisons, Boolean AND, then Boolean OR. Arithmetic associates left. Chained comparisons are rejected. Operators require token separation; start-offset remains one identifier.
  • Nested square brackets group math and inherit its header. Parentheses retain ordinary Lim syntax. Calls and argument records end header inheritance: infix expressions inside them need explicit headers of their own.
  • A function record requires #params, #returns and #body. Contract fields #requires, #ensures and #preserves contain lists of independent clauses and default to empty. Unit results explicitly use #returns = (); and (#return ()). Unknown and duplicate section keys are errors. Parenthesized sections such as (#params {...}) also normalize to canonical functions.
  • : groups the following syntax as parentheses. On the same line it consumes the remaining forms until the newline, the enclosing closing delimiter, or a semicolon. Repeated colons nest: (a : b : c) is (a (b (c))). A colon can appear anywhere a form is expected; it has no special meaning at the head of a list.
  • A colon at the end of a line groups the following indented syntax. Dedent closes the group. Semicolons inside it group statements, just as they do in an explicit parenthesized sequence. An indented header form ends on dedent without another semicolon. Loops accept a body collection written either with explicit parentheses or with colon grouping.
  • In records, key: syntax;, key : syntax;, and key = : syntax; assign that grouped value. Inline entries retain their terminating semicolon; multiline groups close the entry on dedent. Blank/comment lines do not affect scope. Use spaces for indentation. ::, embedded left:right, and prefixed :label remain ordinary identifier text; a standalone colon or a single trailing colon starts a group.
  • At module scope, #fn, #unsafe-fn, #static, #const and #generate accept an unparenthesized name and record. Its closing brace ends the form. Static and constant records require #type and #value.

The formatter retains authored layout in forms using this notation and removes trailing horizontal whitespace. Its canonical S-expression formatting remains available for fully delimited sources. Reader nesting limits also bound trees created by flat infix chains. Surface syntax does not infer contracts or change the exact identity of comparison evidence.

Inline colons also work inside a function's body field:

#fn main {
  #params = {};
  #returns = #u64;
  #body: #return : #u64::add-wrap 20u64 22u64;
}

Lim currently provides:

  • strong static types and explicit types on bindings and parameters;
  • no type inference and explicit types on all bindings and calls;
  • value structs, enums, tuples, and fixed-size arrays;
  • immutable borrowed slices with checked indexing;
  • free-standing functions; concrete specialization is generator-driven;
  • explicit integer width and overflow behavior;
  • native x86-64 code generation using the System V ABI;
  • compile-time constants and read-only statics;
  • source-level generated declarations such as #generate #optional and #generate #result;
  • pure user-defined syntax generators with a restricted #gn-* operation set;
  • no recursion, allowing the compiler to calculate a finite call depth.

User-defined traits, methods, closures, and other source-level indirection mechanisms are not part of the current language. Built-in Send and Sync properties are structural. References and raw pointers may point to aggregate values; #get projects fields through a reference. Direct #deref and #deref-set support scalar values and aggregates that fit the native value registers. Large aggregate returns, arguments, dereferences, and reference projections use the compiler's explicit indirect aggregate storage path.

Shared allocator state and cells

Dynamic allocation follows the concrete allocator ABI in allocator.md. Allocator values are passed explicitly and generated collections retain an immutable allocator reference; interior mutability belongs to the allocator implementation.

#generate #cell is a standard-library generator in library/cell.lim, not a builtin type. Each invocation explicitly names the concrete type and three free-standing functions. It currently accepts the integer widths supported by #atomic (#i8/#i16/#i32/#i64, #u8/#u16/#u32/#u64, and #usize); it does not support floats, pointers, or enums. The generated get/set functions take a shared reference to the concrete cell and never return a reference to its contents:

(#alias cell-generator = ../library/cell.lim::#cell)

(#generate cell-generator #u64 CellU64 CellU64::create CellU64::get CellU64::set)

(#struct Arena () { cursor = CellU64; })

#fn advance {
  #params = { cursor = (#ref CellU64); };
  #returns = #u64;
  #body:
    #let next #u64 [#u64 #wrap; (CellU64::get { cell = (#clone cursor); }) + 1u64];
    CellU64::set { cell = (#clone cursor); value = next; };
    #return next;
}

An aggregate that stores a reference retains a borrow of its owner for the rest of the containing function. It cannot be returned if that borrow points to a local, and reference-bearing fields cannot be replaced. Mutable references may be stored in structs and enum payloads; they retain an exclusive borrow of their source and cannot be cloned. The generated cell is linear, but its relaxed atomic storage makes it both Send and Sync. A read-modify-write sequence such as advance is not an atomic increment; use #atomic-fetch-add when multiple threads must update one counter.

For coordinated shared mutable state, use explicit atomic operations. The atomic API supports #i8/#i16/#i32/#i64, #u8/#u16/#u32/#u64, and #usize. Each operation uses the width's naturally aligned x86 memory access; Lim's current local and aggregate storage is at least eight-byte aligned:

(#let-mut counter (#atomic #u64) (#atomic-init #u64 0u64))
(#atomic-fetch-add (#borrow counter) 1u64 #memory-acq-rel)
(#let observed #u64 (#atomic-load (#borrow counter) #memory-acquire))
(#atomic-store (#borrow counter) observed #memory-release)

(#atomic-exchange reference desired #memory-order) replaces the value and returns the old scalar. Compare-exchange has these explicit forms:

(#atomic-compare-exchange reference expected desired #memory-acq-rel #memory-acquire)
(#atomic-compare-exchange-weak reference expected desired #memory-release #memory-relaxed)

Both return (#tuple #bool ScalarType): success followed by the observed old value. On failure memory is unchanged; the observed value can be used for an explicit retry. Expected and desired must match the atomic scalar. Success accepts every #memory-* order; failure accepts relaxed, acquire, or seq-cst, and cannot be stronger than success. In particular, release success permits only relaxed failure; acquire failure requires acquire, acq-rel, or seq-cst success. Release/acq-rel failure orders are invalid.

The x86-64 backend emits memory xchg for exchange (implicitly locked), and lock cmpxchg for both compare-exchange forms. Narrow observed values are sign- or zero-extended according to the scalar type. These instructions provide stronger hardware ordering than relaxed operations require. Weak compare-exchange is currently implemented without spurious failure; callers must still allow spurious failure for future backends. Atomic operations provide no scheduling fairness or starvation guarantee. See examples/atomic_claim.lim for two workers claiming the same state; both tasks are spawned before either is joined.

Loads accept #memory-relaxed, #memory-acquire, or #memory-seq-cst; stores accept #memory-relaxed, #memory-release, or #memory-seq-cst. Fetch-add accepts any of those plus #memory-acq-rel. Invalid order/operation combinations are compile-time errors. The native x86_64-sysv backend relies on aligned 8-bit, 16-bit, 32-bit, and 64-bit x86 atomic accesses; acquire and release loads/stores use x86 TSO ordering, seq-cst stores use an exchanging instruction, and read-modify-write uses a locked instruction. This API is not available for #i128 or #u128. Unsafe #send/#sync overrides remain the author's soundness promise and do not replace atomic operations.

Borrows of struct fields are tracked as places. While point.x is borrowed, an access to point.y is allowed, but an access to point.x or to the whole point is rejected. A field reference derived through a mutable reference temporarily suspends that parent reference; #drop releases the derived loan and restores the parent borrow.

Send and Sync properties

Send means a value may be transferred to another thread; Sync means a shared reference to the value may be used from another thread. The compiler derives both properties recursively for structs, enums, tuples, and arrays:

  • Scalar types are Send + Sync.
  • Raw pointers are neither Send nor Sync.
  • Generated #generate #cell types use relaxed atomic storage and are Send + Sync for their supported integer widths.
  • (#atomic T) is both Send and Sync only for the supported atomic integer widths listed below.
  • (#ref T) is Send when T is Sync, and is Sync when T is Sync.
  • (#ref-mut T) is Send when T is Send, and Sync when T is Sync.
  • An aggregate has a property only when all of its stored fields/payloads have that property.

Unsafe native or opaque types may opt in explicitly:

(#struct NativeResource () { handle = (#ptr #u8); })
(#unsafe-impl #send NativeResource)
(#unsafe-impl #sync NativeResource)

These declarations are promises by the author and override the structural result for that property. They must only be used when the type's invariants make cross-thread transfer or shared access sound. Generic-type overrides are currently rejected; duplicate or undeclared targets are errors. The #generate #thread-spawn with ((task TaskType) (worker worker-function)) validates a monomorphic worker's parameter and return types against Send. It generates TaskType-spawn and TaskType-join functions and a private native thread entry point; user code never passes a function pointer. Spawn arguments are copied into a private task packet before the worker starts. Scalar and aggregate arguments/results use the compiler's native calling convention. Spawn returns TaskType-spawn-result: TaskType-spawn-ok carries the opaque task handle and TaskType-spawn-error carries an allocation or thread-creation error. Join returns TaskType-join-result: TaskType-join-ok carries the worker result; TaskType-join-error carries the still-owned task handle and native error code. This distinguishes runtime failure from valid zero-valued results and allows the caller to retry a failed join. A failed join does not release captured borrows or free the task packet.

On the Linux x86-64 backend, generated threads use direct kernel calls, not libc or pthreads. mmap reserves a stack and task packet; mprotect leaves the bottom page inaccessible. The compiler sizes each worker's stack from its emitted call graph, rounded to pages with a 64-KiB minimum and allowances for the entry trampoline and red zone. An unknown or unbounded worker call path is a compilation error rather than a guessed stack size.

The native clone trampoline starts execution on the new stack. The parent and child share a kernel-managed TID word: parent-TID publication avoids an immediate-exit race, and child-TID clearing wakes a shared futex after exit. Join waits for that clearing before copying the result and unmapping the stack/packet. EINTR and EAGAIN retry internally; other futex errors retain the task handle in the join-error result. Allocation/protection and creation failures keep the existing distinct spawn-error variants. See the Linux clone contract and clear-child-TID contract.

Workers have no libc TLS: their FS base is explicitly zero, and reachable foreign or indirect callees are rejected, including calls through Lim helper functions. Explicit FFI outside worker call graphs remains available. Unsafe worker assembly must obey the same no-foreign-runtime and stack contracts; it must not terminate the thread early or change its clear-child-TID address. Installing custom signal handlers is also an unsafe responsibility: block their signals before spawning, arrange a worker-owned alternate signal stack, then unblock them. The computed Lim stack bound does not cover arbitrary signal-handler frames. The backend provides no pthread cancellation or TLS destructor behavior.

examples/kernel_threads.lim exercises concurrent parent/worker progress, shared PID/distinct TIDs, the worker TLS boundary, repeated joining, and stdout. tests/kernel_threads.rs checks static ELF linkage, argument/result layouts, nested workers, large stack frames, and an actual guard-page fault. Its opt-in ptrace tests also verify kernel calls and inject spawn/join failures.

For inspection, (#generate #thread-spawn ((task TaskType) (worker worker))) materializes in .lim/ as a #thread-task declaration containing explicit #thread-task-spawn and #thread-task-join builtin signatures, followed by #enum declarations for their results. The spawn signature exposes TaskType-spawn; its result enum contains TaskType-spawn-ok and TaskType-spawn-error. The join signature exposes TaskType-join, and its result enum contains TaskType-join-ok and TaskType-join-error. The compiler validates and reuses matching signatures and enums rather than synthesizing duplicates.

Task handles are affine: match spawn results, and join each successful task handle exactly once. The join error arm must retain or retry the returned handle; discarding either generated result is rejected. References captured by a worker remain borrowed until a successful join; shared captures require Sync, mutable captures exclude parent access until join. These restrictions are checked statically. Unsafe #send/#sync overrides are promises, not synchronization: the author must ensure the underlying resource remains sound under concurrent access.

Inferred lexical borrows

Lim's initial borrow model checks lexical borrow scopes without lifetime annotations. A shared borrow is written as:

(#borrow value (#u64::add-wrap value 2))

and a mutable borrow as:

(#borrow-mut value (#block (#set value 42) value))

The three-expression form borrows the owner for the duration of the body. The two-expression form produces a reference:

#fn first {
  #params = { value = (#ref #u64); };
  #returns = (#ref #u64);
  #body:
    #return value;
}

Multiple shared borrows may overlap, but a mutable borrow cannot overlap any other borrow, and a shared borrow cannot overlap a mutation. References to locals cannot escape their function; incoming reference referents and globals may be returned. A by-value parameter's own storage is local too: returning (#borrow parameter) is invalid even if the parameter itself contains references. Loading one of those incoming references preserves its external referent instead. #deref reads through a reference, and #deref-set writes through a mutable reference when the target fits the native value registers. The known target type is used for aggregate RHS values, including one-word structs. Writing a zero-sized aggregate evaluates both operands but writes no bytes. A field reference can be derived from a named reference to a struct with (#borrow (#get reference field)) or #borrow-mut for an exclusive field reference. The derived reference retains the original referent's borrow: it cannot escape when that referent is local, and a mutable parent reference is suspended while its derived field reference remains live. Tuple and array projections use #get and #index; enum payload fields use (#get-payload reference Variant index). Each variant has zero or one payload. Use a named struct as the payload when a variant needs multiple fields. Projections may also start at an owned local, without borrowing the entire aggregate first: (#borrow (#get owner field)). Nested struct, tuple, array, and enum-payload projections address the original storage; a dynamic index is evaluated once before the borrow's body. Mutable borrowing requires a mutable local or an exclusive reference root. The same rules apply to #pin-borrow and #pin-borrow-mut, and reborrowing through a pinned reference preserves pinning. A projection cannot borrow a computed aggregate temporary. When crossing a reference-valued field, bind that reference first so the next borrow has an explicit reference root. See examples/owned_field_borrow.lim.

Reference-valued fields may be projected through nested aggregates; their original source borrow remains active for as long as the containing aggregate is live.

(#struct Point () { x = #u64; y = #u64; })

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut point Point: #struct-literal Point { x = 1; y = 2; };
    #let point-ref (#ref-mut Point): #borrow-mut point;
    #let y-ref (#ref-mut #u64): #borrow-mut (#get point-ref y);
    #deref-set y-ref 42;
    #return: #deref y-ref;
}

Raw pointers and unsafe blocks

Raw pointers are explicit and distinct from references. (#ptr T) is an immutable raw pointer and (#ptr-mut T) is a mutable raw pointer. Taking an address and reading or writing through a raw pointer must occur inside an #unsafe block:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut value #u64 40;
    #return:
      #unsafe
        (#block
          (#let pointer (#ptr-mut #u64) (#addr-of-mut value))
          (#ptr-write pointer 42)
          (#ptr-read pointer))
}

Functions with caller safety obligations use #unsafe-fn instead of #fn. Their signatures otherwise have the same shape. Every call uses #unsafe-call inside #unsafe, including calls from another unsafe function. #call rejects unsafe functions even inside #unsafe, and #unsafe-call rejects safe functions. The declaration does not make its body implicitly unsafe: raw operations and unsafe calls still need an explicit block.

#unsafe-fn read-byte {
  #params = { pointer = (#ptr #u8); };
  #returns = #u8;
  #body:
    #return: #unsafe (#ptr-read pointer);
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let value #u8 42u8;
    #return: #as (#unsafe (#unsafe-call read-byte { pointer = (#addr-of value); })) #u64;
}

Imports and generated declarations preserve the calling requirement. Implicit entry points (main, aggregate clone hooks, and thread workers) must be safe; use a safe wrapper that explicitly discharges the unsafe function's obligations. Generator capability contracts currently describe safe operations, so an unsafe operation does not satisfy one. The Linux library uses this contract for all raw-pointer wrappers and integer-only APIs with hidden memory or execution-state obligations. Reference-bounded byte/time helpers remain safe. See the syscall caller contracts.

The operations are #addr-of, #addr-of-mut, #ptr-read, #ptr-write, and (#ptr-offset pointer element-index). (#ptr-null (#ptr-mut T)) or (#ptr-null (#ptr T)) constructs a typed null pointer; constructing one is safe, but dereferencing it is not. (#ptr-is-null pointer) safely tests whether a raw pointer is null without consuming it. (#ptr-address pointer) returns the machine address as #usize without dereferencing it; it can check Linux error-pointer returns before any access. The offset consumes a raw pointer and returns a pointer with the same mutability and pointee type; its index must be #usize. Offsets use the pointee's byte width (for example, *mut u8 advances one byte). Byte-offset multiplication and address addition are checked for overflow and trap on overflow. Reads and writes access only the pointee's width. Writing requires (#ptr-mut T). Reads and writes do not check allocation bounds, and raw-pointer operations are rejected outside #unsafe; callers must uphold pointer validity and bounds themselves. #ptr-borrow and #ptr-borrow-mut also require #unsafe; their first argument is a reference used as the inferred lifetime anchor, and the second is the pointer to the referenced value. The #pin-ptr-borrow variants require a pinned-reference anchor and preserve the pinned-reference type/provenance. The caller must ensure the pointer is valid, stable, and uniquely accessible as required for the full anchor lifetime. These forms do not make allocation or pointer validity safe by themselves.

Pinning is exposed through generated opaque objects rather than a special binding statement. Import library/pin.lim and declare a concrete API:

(#generate #pin ((type Frame) (name PinnedFrame) (fields ((value #u64)))))
(#generate #pin-scope ((type Frame) (pin PinnedFrame) (name with-pinned-frame)
  (run drive-frame) (destroy destroy-frame) (result #u64)))

#generate #pin emits opaque PinnedFrame and PinnedFrame::Shared handles, unsafe constructors, and PinnedFrame::Read::value / PinnedFrame::Write::value free functions (plus the shared reader). Field types are literal generator inputs; ordinary checking verifies them and rejects moving linear fields or replacing fields that do not satisfy the pinned-field restrictions. Optional copy true emits whole-value readers and a writer only after checking a structural Copy proof. All implementation functions are inspectable in the generated cache. For linear fields, projections ((child PinnedChild)) generates PinnedFrame::Project::child and PinnedFrame::ProjectMut::child, returning the existing concrete child pin handles without moving the field. Shared handles also get a shared projection. Projection consumes the parent handle; it does not leave a second mutable handle to the same storage. Derived handles retain their source's borrow and cannot outlive it. Unsafe PinnedFrame::into-view consumes a handle and exposes its low-level pinned reference for trusted implementations; it does not unpin or move the referent.

The same declarations also generate PinnedFrame::BorrowMut::child, taking ((pin (#ref-mut PinnedFrame))), and PinnedFrame::Borrow::child, taking ((pin (#ref PinnedFrame))). Shared wrappers have their own shared ::borrow function. These reborrow the child without consuming the parent handle. Disjoint mutable child fields can coexist, as can overlapping shared views; overlapping exclusive access is rejected at the offending call argument. Callee footprints follow the wrapper's actual pinned pointer slot, including helper calls and transferred child arguments, not just its stack address. Forgetting a wrapper does not unpin or destroy its referent: child views still retain that referent, and prevent scope escape or heap release. See examples/pin_projection_borrows.lim for two independently writable children.

with-pinned-frame takes value Frame, initializes private stack storage, and calls drive-frame with pin PinnedFrame. It then calls destroy-frame with a fresh pin handle before retiring that storage in place. The run function returns the specified result type; the destruction function returns unit. Both functions must consume their handles explicitly. The original storage is inaccessible to callbacks, even if they forget their handles. Returned borrows cannot escape the scope, and cancellation/resource cleanup must be implemented in the destruction callback. No function pointers, lambdas, #let-pin, or #pin-end are needed. See examples/stationary_pin.lim.

For an initialized local, (#pin local) creates an exclusive (#pin-ref-mut T) and requires a #let-mut binding. (#pin-shared local) creates a shared (#pin-ref T) and also accepts immutable locals. Neither accepts a temporary, projection, reference variable, top-level constant, or static: use #pin-borrow/#pin-borrow-mut for projection reborrows. Both local operations permanently freeze the original storage, including Copy locals. Forgetting the reference ends its loan, but does not allow moving or assigning the original local again. A branch that may pin a local also freezes it after the branch joins. Copy values can still be read or copied from frozen storage when normal loan rules permit: copying a Copy value does not move the storage itself. Whole-local assignment remains forbidden. Each new loop iteration initializes fresh local storage; explicitly end the previous iteration's local after its views end.

(#struct LocalJob (#linear) { state = #u64; })

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut job LocalJob: #struct-literal LocalJob { state = 0u64; };
    #let view (#pin-ref-mut LocalJob): #pin job;
    #pin-set-field view state 42u64;
    #let answer #u64: #get view state;
    #forget view;
    #forget job;
    #return answer;
}

Ordinary named functions can take pinned references, so multiple local pins can be selected and polled in branches without callbacks or generated wrappers. An ordinary reference does not satisfy a pinned-reference parameter. Local pins cannot escape their storage scope, and overlapping mutable loans are rejected. After all references end, explicit #forget owner ends the local in place; it is not a destructor and performs no resource cleanup. Perform any required in-place cleanup first. Local pinning does not change #pin-own: that heap owner remains movable because its allocation stays stationary.

Low-level pinned-reference operations remain compiler primitives for generated code and unsafe implementations. Ordinary #pin-borrow permanently prevents moving a linear local after its first pin, even after its last view is forgotten; explicit #forget/#drop ends that local's lifetime. Plain Copy referents retain short-lived borrow rules. Nonmoving Copy field operations on pinned linear locals remain allowed, subject to the existing field-loan checks.

(#pin-own T) is a linear, movable owner of stationary heap storage. Unsafe #pin-own-of pointer value initializes uniquely owned writable allocation storage using Lim's native value layout and adopts it; safe #pin-own-borrow and #pin-own-borrow-mut borrow the allocation identity, not the handle's address. Views remain valid across handle moves, aggregate moves, and function returns. An optional allocator-reference argument keeps the allocator borrowed for the entire view lifetime. Forgetting an owner leaks the allocation rather than moving, freeing, or unpinning its contents. In-place cleanup precedes unsafe #pin-release, which returns the pointer for deallocation. Retained views block release, including release in called helpers. Calls that obtain conflicting pointee access also reject retained views; a pure owner-forwarding function does not. The opaque owner generated by #generate #pin-box exposes native pinned references; its destruction callback accepts pin with type (#pin-ref-mut T) for in-place cleanup. Transferring an owning allocation to a thread requires retirement of its existing pointee views. The caller still guarantees validity, alignment, unique raw ownership, and retirement of untracked raw pointers. Reference-bearing and nested owning-pin pointees retain their contents' loans through owner moves, return summaries, and field projections. Allocating storage does not extend a referent's lifetime. Heap writes, including helper-call writes, update retained loans in the owning allocation. A definite write to one concrete field retires that field's old loan and records its replacement; uncertain writes and control-flow joins keep all possible referents. A reference already loaded from the old field remains an independent live loan. library/pin_box.lim defines the #generate #pin-box generator, which takes exactly the named options type, allocator, name, and destroy. allocator is a literal bundle root exposing ::State, ::Error, byte-pointer ::Allocation, safe ::allocate, and unsafe ::deallocate. Its private typed adapter converts the byte pointers. It generates an opaque named linear heap-owner type and create, shared-borrow, mutable-borrow, and destroy functions. Its borrow functions return native #pin-ref and #pin-ref-mut values. examples/pin_box.lim demonstrates moving a handle while a view stays live. For an owner Box, generated symbols include Box::CreateResult, Box::created, Box::allocation-failed, and Box::create / Box::borrow / Box::borrow-mut / Box::destroy.

library/pin_rc.lim defines #generate #pin-rc with the same named options and allocator bundle convention, and generates named linear reference-counted owners with create, clone, shared-borrow, mutable-borrow, and destroy functions. This Rc is single-threaded and is neither Send nor Sync; it has no weak-reference handles. Mutable borrowing is available only while the handle is the unique strong owner. Destroy every borrowed view before destroying a handle, because the final handle destruction runs the pointee destructor in place and releases the allocation. For an owner Shared, generated symbols include Shared::Allocation, Shared::CreateResult, Shared::MutResult, and Shared::create / Shared::clone / Shared::borrow / Shared::borrow-mut / Shared::destroy; enum cases include Shared::unique and Shared::Shared.

For an owner named PinnedFrameRc, a private adapter converts the bundle's (#ptr-mut #u8) success payload to a pointer to the generated PinnedFrameRc::Allocation control block. The generated functions pass that block's size and alignment to the allocator and deallocator. Both Box and Rc request only allocate and deallocate adapters; their bundles may omit grow. Destruction hooks are explicit safe functions taking ((allocator (#ref Root::State)) (pin (#pin-ref-mut Element))) and must perform explicit in-place cleanup. examples/pinned_box_async.lim and examples/pinned_rc_async.lim poll generated futures through these native pinned references, including after moving the owning handle.

An async function can initialize an owner containing an external reference after an await and retain it across later suspension. Its source remains borrowed through Pending; Ready or explicit state-specific cancellation must consume the owner before the source can be modified. Structural reference tracking includes references inside nested owning pins, not just inline fields. examples/async_heap_reference.lim demonstrates this case. It is not a frame-local self-reference: general delayed frame-owner initialization and named pinned poll-handle recycling remain separate checked-analysis work.

#pin-read and #pin-write are lower-level unsafe operations for compiler- generated pinned state machines. They access aggregate referents at their existing storage address. A read can duplicate a linear value, and a write can invalidate references derived from the pinned value; callers must prove exclusive access, preserve any displaced ownership they need, and ensure no derived references remain. Ordinary code should use safe field operations instead; safe code cannot replace a pinned referent.

For a pinned handle proven to address one whole owned local value, the compiler tracks a linear #pin-read as a move: the original value's cleanup obligation is satisfied, and repeated loads, alias reads, and reborrows of that uninitialized storage are rejected. A matching #pin-write requires prior consumption before replacing a linear value and restores its cleanup obligation. The loaded value keeps its own retained reference slots, not the container address. Moving a reference-bearing holder transfers its loans; copying one retains both sets until the corresponding values are released. See examples/pinned_local_move.lim for local move/restoration and returning a loaded reference-bearing value from a branch-local holder.

For #deref-set and unsafe #pin-write, a destination proven to be one whole owned local value retains the RHS's reference fields and their original referent loans. Replacing a holder releases its previous stored loans; moving an exclusive-reference holder transfers its loans and keeps derived-reference parents suspended until the restored holder is consumed. Shared copies keep their respective loans. A local reference cannot be stored in external storage or survive its referent's scope, even when the write is indirect. See examples/borrowed_variant.lim and examples/pinned_holder_restore.lim. This whole-local registration rule does not enable projected, ambiguous, parameter, global, or lifetime-only destinations.

Whole ordinary #deref loads from borrowed parameters preserve the retained reference fields of the loaded value. Each field remains tied to its original input slot through function returns and caller substitution, rather than to the address of the container. A shared container cannot grant exclusive access through a stored mutable reference. See examples/borrowed_whole_load.lim. Parameter #pin-read loads preserve those retained value slots as well; see examples/pinned_parameter_load.lim. This provenance rule does not supply a complete parameter move/restore contract or prove variant-conditioned async frame accesses. The operation remains unsafe.

This local rule does not establish complete contracts for parameter-loaded frames, projected/ambiguous storage, or lifetime-anchored raw pointers. Those unsafe protocols still require the caller's guarantees; full referent and variant-conditioned async ownership analysis remains under development.

#pin-set-field is the checked field-wise operation for scalar/fieldless-enum and shared-reference struct fields. It writes only that field, so a state tag can change independently and an immutable reference can be established after the struct is pinned without moving the referent. The borrow checker tracks the stored reference as part of the owner: it rejects overlapping field replacement and keeps the owner pinned and borrowed until the reference field is cleared. This operation is not a way to make a movable async frame self-referential; generated frames still need stable storage slots and cancellation-aware internal-loan handling.

Ordinary calls also check statically resolved internal owner loans against the callee's writes and destructive accesses, including nested calls and paths that trap instead of returning. A disjoint field update is allowed; overwriting the internally borrowed field reports E4100 at the caller's argument and labels the callee access. Checked enum tests and assertions retain entry-tag constraints for conditional initialization, rather than treating a tag written by the initializer as an incoming constructor. See examples/pinned_self_reference.lim for an ordinary-call example. This additional rejection check is not permission to reborrow a whole parent while its children remain live. Context-sensitive exclusive loans in conditional enum payloads still require incoming/fresh-family correlation and remain subject to the existing conservative borrow checks.

#asm embeds target assembler at an expression site. Its form is (#asm ResultType ((register value) ...) "instructions"): each value is evaluated and loaded into its named 64-bit general-purpose register, and the result is read from rax (or discarded for ()). The current backend uses GNU Intel-syntax x86-64 assembly. #asm is unsafe and must be inside #unsafe. The assembly must leave rsp and rbp unchanged, must not return or jump out of the surrounding function, and must obey the platform ABI for any registers it changes; the compiler preserves callee-saved GPRs but cannot verify raw instructions. Syscall numbers and register conventions are OS/architecture specific, so select implementations with #cfg rather than assuming one assembly sequence is portable.

For Linux x86-64 kernel entry without hand-written register shuffling, unsafe #linux-syscall takes an explicit result type, syscall number, and up to six arguments. It emits the syscall instruction directly; no libc wrapper is called. Integer arguments are passed as machine words, raw pointers as-is, and Lim references have their internal low-bit tag removed before being passed as addresses. Raw syscall failures are returned as negative errno values. The primitive is deliberately unsafe because the kernel interprets syscall numbers, flags, descriptors, and pointer/length pairs according to Linux ABI contracts.

#fn process-id {
  #params = {};
  #returns = #i64;
  #body:
    #return: #unsafe: #linux-syscall #i64 39usize ();
}

library/linux_x86_64.lim builds byte input/output, process helpers, and file-descriptor operations (openat, positional and sequential IO, metadata, directory queries, resource limits and usage, advice, locking, allocation, descriptor duplication, anonymous files, wall-clock/process-time queries, and private futex operations) on this primitive. The low-level pointer wrappers do not validate kernel buffer ranges; callers must uphold pointer validity and length preconditions. These wrappers are #unsafe-fn: the compiler requires #unsafe-call inside #unsafe, even for null pointers or zero-length buffers. Safe reference-bounded helpers use #call. For example, this unsafe forwarding function passes its caller's buffer contract through to the low-level read wrapper:

(#alias linux-read = ../library/linux_x86_64.lim::linux-read)
#unsafe-fn read-buffer {
  #params = { fd = #i64; destination = (#ptr-mut #u8); count = #usize; };
  #returns = #i64;
  #body:
    #return:
      #unsafe (#unsafe-call linux-read { fd = fd; destination = destination; count = count; })
}

Building and running

For the standard library's measured syscall breadth, test commands, and remaining safety/coverage gaps, see syscall coverage.

The repository contains a Nix flake with the Rust toolchain:

nix develop
nix develop --command cargo test --all-targets
nix develop --command cargo doc --no-deps --open

Compile Lim source directly to a native executable from the Nix development shell. The backend emits inspectable assembly; its x86-64 encoder and ELF writer produce the executable without external build tools. By default, the output is placed beside the input and uses the input filename without its extension. -o selects a different path:

nix develop --command cargo run -- examples/fibonacci.lim
nix develop --command cargo run -- examples/fibonacci.lim -o /tmp/fibonacci
/tmp/fibonacci
echo $? # 55 for the Fibonacci example
nix develop --command cargo run -- --check-examples examples
nix develop --command cargo run -- examples/fibonacci.lim --target x86_64-sysv
nix develop --command cargo run -- --format examples/fibonacci.lim
nix develop --command cargo run -- fmt examples/modules/main.lim

--format retains comments in their surrounding syntax, including nested forms and generator templates. Formatting is idempotent.

The formatter keeps binding names beside their explicit types and callees beside #call or #unsafe-call. Long colon argument lists put each named group on its own line; empty argument lists use (). Short unsafe expressions and single-expression cases stay compact, while multi-expression case bodies are indented as sequences. Function and generator declarations are separated with blank lines.

Formatting uses Lisp-style headers and two-space body indentation. Function signatures stay together, short nested expressions stay inline, and closing parentheses follow the final expression. A #for keeps initialization, comparison, and mutation together, followed by its indented body:

(#for (#let-mut i #u64 0) (#u64::lt (#clone i) 10) (#set i (#u64::add-wrap (#clone i) 1))
  (#assert (#u64::lt (#clone i) 10)))

Ordinary expressions exceeding a target width of 100 columns wrap between arguments. Form headers may exceed that width. Comments and parser shorthand retain their source spelling.

lim fmt INPUT formats the file and its transitive explicit file dependencies within the same library boundary. Dependencies across a boundary are skipped. The read-only --format form remains available to print one formatted file or write it to a separate output path.

Native compilation carries an explicit target description. The supported target/ABI matrix currently has one entry:

Target spellings OS/object format CPU ABI Backend/linker
x86_64-sysv, x86_64-unknown-linux-gnu Linux ELF x86-64 System V native x86-64 assembly, internal instruction encoder and ELF linker

The linker reads ELF object symbol tables directly. When all objects have no unresolved symbols and no libraries were explicitly requested, it links statically without libc, pthread, or a dynamic interpreter. This includes programs importing the direct-syscall Linux library. Unused external declarations alone do not require a runtime. Inline assembly's foreign references are detected from encoded relocations. References between supplied objects are resolved before considering shared libraries. If unresolved references remain, or libraries were explicitly requested, the compiler writes the interpreter, dynamic symbol/string tables, GOT relocations, and shared-library dependencies itself. Supplied ELF64 objects may contain code, read-only data, writable data, and BSS. Source constants and object-file read-only sections occupy a separate readable, non-executable ELF segment; code is read-execute and mutable data is read-write. Unsupported #asm forms or ELF relocations are diagnosed rather than passed to an external tool. All 318 current examples build with external build tools absent from PATH. The object linker currently accepts x86-64 R_X86_64_64, PC32, PLT32, 32, 32S, GOTPCREL, GOTPCRELX, and REX_GOTPCRELX relocations. Direct unresolved PC32 references to sized data symbols in shared libraries use R_X86_64_COPY relocations. TLS data and unsupported relocation forms are rejected with a linker diagnostic. Absolute shared-library symbol addresses stored in writable object sections use dynamic R_X86_64_64 relocations. PC-relative GOT and COPY references may also originate in writable sections. An undefined weak object symbol with no linked object definition resolves to zero; it does not force a shared library dependency. ELF forms outside this supported subset are rejected. The dynamic loader path is read from the compiler's own ELF interpreter when available, with LIM_DYNAMIC_LINKER as an absolute-path override and the conventional Linux x86-64 loader path as a fallback. Shared libraries are located using the loader's directory, target library search paths, and standard Linux paths; their directories are recorded as an ELF runpath. After main returns, the entry stub calls Linux exit_group with its result, not thread-only exit, so outstanding kernel workers cannot change the process's final status. Explicit linux-exit remains thread-only. See exit_group(2).

All other target names (including other operating systems using the System V calling convention) are rejected. Host selection requires both Linux and x86-64. The Rust API exposes TargetDescription and generate_assembly_for_target; the existing generate_assembly API selects the supported host target.

--check-examples recursively parses, type-checks, borrow-checks, and lowers every .lim file under the selected directory. It reports each source file individually and returns failure if any example fails.

--emit-asm INPUT OUTPUT remains available to inspect backend output. --stack-usage INPUT compiles the project through code generation, then reports generated-code stack bounds without invoking the native linker. It accepts --target, --cfg, and --module-path options just like compilation. Every generated #generate expansion is materialized as a readable, content-addressed .lim entry under .lim/generated/, regardless of whether it uses a built-in or a user-defined generator. The digest is derived from the normalized invocation, compiler version, target, complete loaded import forms, and compiler cfg values. A neighboring key file verifies the full key before a cache hit, so a digest collision cannot return unrelated generated source. A checksum over the key and generated bytes detects edited or damaged entries; invalid entries are regenerated. Checksums detect accidental changes and are not an authenticity mechanism against someone who can edit both data and metadata. User-generator evaluation also keeps its lower-level syntax cache in the same directory with an integrity checksum. Cache records are staged under unique names and published atomically; the inspectable-source checksum is published last as a consistency marker. An interrupted or concurrent write is treated as a cache miss and regenerated. Staging files older than one hour are removed when the cache is next read; newer temporary files may belong to active compiler processes and are left alone. There are no numbered generated-source files; deleting .lim/ only causes generators to run and materialized entries to be recreated.

Compile-time configuration

#cfg-if includes only the selected top-level forms. Its condition is built from #cfg-is, #cfg-not, #cfg-and, and #cfg-or; branches contain forms directly, with an optional final #cfg-else branch:

(#cfg-if (#cfg-and (#cfg-is #platform linux) (#cfg-is #feature fast))
  (#fn selected () #u64 (#return 1u64))
  (#cfg-else
    (#fn selected () #u64 (#return 0u64))))

#platform and #os are populated automatically from the compiler host OS (linux, macos, or windows, where applicable); #arch is the target architecture (such as x86_64), and #target is its canonical target triple (currently x86_64-unknown-linux-gnu for the supported backend). Other keys must be passed with --cfg KEY=VALUE; for example, --cfg feature=fast. Command-line settings override automatic values. Configured values are literal symbols or strings in #cfg-is. Excluded forms are removed before imports, generators, name checks, and type checking are processed.

Pass --cfg repeatedly to set several keys. It works in both binary and assembly-output modes; a key supplied more than once uses its last value.

Use --collect-cfgs INPUT to print the sorted, unique cfg keys referenced by the source and its imports. Collection scans every cfg branch, including inactive branches, and follows imports found inside those branches:

nix develop --command cargo run -- --collect-cfgs examples/cfg_platform.lim
# prints: #platform

User-defined generators

Literal syntax bundles

Use #syntax to declare an immutable list of literal syntax, and explicitly splice its elements into another list with #syntax-splice. Neither form evaluates values or infers types. An await protocol can be named once:

(#syntax StepAwait (#u64 Step StepPoll.StepPending StepPoll.StepReady step-poll))
(#await StepAwait step)

The second form expands to (#await #u64 Step StepPending StepReady step-poll step) before async lowering. It is only valid inside an async function. The longer (#await (#syntax-splice StepAwait) step) spelling is equivalent. Both async function generators export a bundle automatically. Supply one explicit protocol name instead of listing all five generated names:

(#generate #async-fn ((protocol WorkAwait) (waker LocalWaker)
  (function (#fn work ((offset #u64)) #u64
    (#return (#await StepAwait (Waiting offset)))))))
// In another async function:
(#await WorkAwait (#call work (($ offset))))

For work, the generated names are Work::Task, Work::Poll, Work::Pending, Work::Ready, and Work::poll. The exported declaration is (#syntax WorkAwait (#u64 Work::Task Work::Pending Work::Ready Work::poll)). #generate #async-fn-pinned instead generates Work::Frame and exports (#syntax WorkAwait (#u64 (#pin-ref-mut Work::Frame) Work::Pending Work::Ready Work::poll)). Callers must pin a frame explicitly before awaiting that protocol. Both generated task and frame structs are #opaque: callers use their constructor, poll and cleanup functions, not their internal fields. This protects the initialization invariants used by generated unsafe accesses. Pinning alone guarantees address stability, not initialization or alias safety. Generated task, result, variant, and poll names come from the source function name. Supply : protocol to select the exported bundle name. Protocols are collected after imports, generators and cfg selection, before await expansion, so functions can refer forward to one another's protocols. Duplicate bundles and declaration collisions are rejected. The bundle appears in the same inspectable, hash-cached generated file as the function's code. This shorthand supplies types explicitly; it adds neither type inference nor implicit pinning, allocation or cancellation.

On the graph route, pinned functions can request post-terminal access to reference-free Copy parameters with : access ((amount AmountAccess)). This emits AmountAccess::read and AmountAccess::replace ordinary functions with pinned frame receivers; the latter also takes a named value argument. They assert completion/cancellation and cleared loans before accessing the same stationary storage. They do not restart the future, infer lifetimes, or allow moving its frame. Without an access request no accessor bodies are generated. See parameter access.

The default graph route can also be selected with --cfg async-lowering=graph. It uses the same await protocol names, independently checked ordinary generated code, and a source-named cleanup record instead of the legacy per-state cancellation interface. Warm hash hits skip emission. Unsupported graph cases fail closed; there is no publicly selectable legacy route or fallback. See graph async lowering for the cleanup contract, supported guards/scoped borrows, and current limitations.

Bundles can also supply function parameters or named call arguments. Definitions are top-level, may refer forward to other bundles, and may contain nested splices. Names must be unique across declarations; cycles, unknown names, malformed definitions, and splices outside a surrounding list are errors. File dependencies and cfg selection happen first; aliases resolve bundle names and referenced identifiers to their defining files. Quoted syntax and generator templates stay literal until emitted. Generated bundle declarations are supported, and ordinary type, borrow, and linearity checking still applies to their expanded code.

Generator declarations

Generators are compile-time syntax functions. Their parameters receive the invocation arguments literally; generator values are immutable syntax nodes: symbols, literals, or lists. A generator returns a list of top-level forms, which are expanded before ordinary Lim parsing and type checking.

Language and standard-library generator names are reserved and start with #: for example, (#generate #optional ((type #u64) (name MaybeU64))), #generate #cell, and #generate #utf8-view. User generators use ordinary names, such as #generate make-record. The #generate keyword invokes generation/import; a generator name's # identifies a reserved name, not a different execution or caching mechanism. Standard-library generators remain ordinary immutable Lim declarations and must be imported before use. Their shipped declarations cannot be redefined. All #-prefixed names are unavailable for user declarations, including declarations emitted by generators. There are no compatibility aliases for the old unprefixed builtin spellings; unprefixed names belong to users, including names such as optional or cell.

Capabilities are explicit declarations for generator requirements. A concrete type opts in with #capability, and a generator parameter can require one:

(#fn u64-less ((left (#ref #u64)) (right (#ref #u64))) #bool
  (#return (#u64::lt (#deref left) (#deref right))))
(#capability sortable #u64
  ((u64-less ((#ref #u64) (#ref #u64)) #bool)))
(#gn make-sortable ((element sortable))
  `((#type Sortable ,element)))
(#generate make-sortable #u64)

The list after a generator's name is its parameter declaration list, not a pattern match. A bare symbol such as name declares an ordinary literal-syntax parameter. A pair such as (element sortable) declares one parameter that requires a capability; it does not destructure the invocation argument. All invocation arguments are literal syntax; there is no implicit registry lookup or distributed syntax expansion. This mirrors function signatures, where each nested pair declares one named parameter and its type.

parameters := (parameter ...)
parameter  := name | (name capability-name ...)

For example, (#gn alias (name target) ...) has two literal-syntax parameters. (#gn sortable ((element sortable)) ...) has one parameter named element requiring the sortable capability. Likewise, ((left right)) declares one parameter named left with a capability annotation right; it never binds two names. Nested lists in the name or annotation position are rejected as malformed declarations. No implicit destructuring takes place; use #gn-first, #gn-rest, or #gn-for-each inside the generator body to inspect literal list arguments.

Each capability declaration lists concrete free-standing operations and their full argument/return types. Before any generator runs, the compiler verifies that every named function exists and exactly matches its declared signature. A missing capability reports the parameter, capability, and concrete type; there are no implicit structural or interface requirements hidden inside a generator. Capability definitions are part of the generated-code cache key, so changing an operation contract cannot reuse expansions made under an older contract.

(#gn aliases (pairs)
  (#gn-for-each pair pairs
    (#gn-list
      (#gn-symbol "#type")
      (#gn-first pair)
      (#gn-first (#gn-rest pair)))))

(#generate aliases ((Byte #u8) (Word #u16)))

Generator helpers can be declared with #gn-fn and called with #gn-call. They take and return only syntax values (symbols, literals, or lists), so predicate booleans remain internal to conditionals. Helpers may call other helpers, but direct or indirect recursive calls are rejected. For example:

(#gn-fn make-alias (name target)
  `(#type ,name ,target))

(#gn aliases (pairs)
  `(,@(#gn-for-each pair pairs
       (#gn-call make-alias
         (#gn-first pair)
         (#gn-first (#gn-rest pair))))))

Backtick starts a syntax template, comma evaluates one generator expression inside it, and comma-at splices a list of syntax values into a template list. Unquote and splice are valid only within a backtick template, and splicing a non-list is an error. Nested templates preserve nested unquotes. These reader forms are generator-only; they do not evaluate Lim code or add runtime values. The lower-level #gn-list and #gn-symbol operations remain available.

#gn-gensym evaluates its string hint and returns a fresh syntax symbol. The hint must parse as exactly one non-keyword ordinary identifier. Generated symbols remain ordinary syntax-symbol values, so they can be reused in the generated declaration and its references; they do not introduce a new syntax datatype. Each evaluation is fresh within its deterministic invocation scope. Use a #gn-fn helper to pass one generated symbol through all places that need to refer to the same binding. Identical generator invocations still deduplicate, and cold or warm cache runs produce the same output.

Names beginning with the compiler-owned lim.gensym. prefix are reserved. Source code cannot name them, and #gn-symbol and #gn-symbol-append cannot forge or alter them. This facility does not automatically make ordinary generated symbols hygienic: public API names passed to a generator remain literal names, and ordinary generated identifiers still undergo the usual duplicate-name, parsing, type, and borrow checks. Source no-shadowing rules are unchanged, and generated output is validated as well. See examples/gensym.lim for a helper that reuses one fresh local name in a generated function.

The generator builtins are #gn-gensym, #gn-if, #gn-equal, #gn-symbol?, #gn-list?, #gn-symbol, #gn-list, #gn-length, #gn-first, #gn-rest, #gn-get, #gn-symbol-append, #gn-variant, #gn-for-each, #gn-call, and #gn-error. #gn-get looks up a literal key in a named syntax list without introducing a new dictionary type. #gn-symbol-append constructs concrete API identifiers by joining the base and suffix with ::, for example Frame and "read" become Frame::read. Nested calls produce names such as Frame::State::Value. #gn-variant joins an enum type and uppercase variant suffix with ., for example (#gn-variant State "Ready") produces State.Ready. These are ordinary identifiers, not namespaces or proof of generator provenance. #gn-for-each is the only iteration construct; there are no general loops or mutable generator values. #gn-error fails expansion with the supplied message. Generators cannot perform IO or call runtime functions. Recursive expansion is rejected. Repeating an invocation with the same generator name and structurally identical literal syntax arguments emits its output only once. Each compilation allows at most 200,000 generator evaluation steps, 128 nested expansions, and 1,000,000 generated syntax nodes; exceeding a limit is a compile-time error. A #gn-for-each binding cannot shadow a generator parameter or an enclosing iteration binding; sibling iteration forms have independent scopes. Unknown #gn-* operations are reported as generator errors with invocation and definition locations.

Ordinary generated identifiers are not hygienic. Pass intended public declaration names as literal arguments; use #gn-gensym only for fresh compiler-reserved local names, and explicitly pass each generated symbol to every generated reference that must resolve to it. Different invocations can use distinct public names while their internal generated locals remain fresh.

Generator-to-generator contracts

Generators can require that public inputs were emitted by a particular generator, without reading its output during expansion:

(#require-generated Work::Frame #async-fn-pinned
  (Work::Poll Work::Poll.Pending Work::Poll.Ready Work::poll))

The first identifier and optional companion identifiers must share one invocation of the named generator. Requirements are checked after expansion, so they may appear before the producer invocation. They neither schedule generators nor inspect unfinished distributed enums. Ordinary typechecking still checks every generated declaration and call.

The compiler records actual generation ancestry. Handwritten lookalikes or unrelated generators cannot claim that origin. Wrappers retain both their own origin and the nested producer's origin, including deduplicated invocations. Cached output is recorded under the actual invocation just like fresh output; source comments and generated properties do not grant provenance.

Imports

Distributed enums collect variants from active imports and generator outputs. Declare (#distributed-enum Error ()) once, and add individual variants with (#enum-contribute Error (Failure #u32)). After expansion, the compiler merges identical variants by name, rejects conflicts, and compiles one ordinary enum. See collections and tasks for the full rules and cooperative async generators. General distributed syntax is not supported.

Struct and enum declarations require a property list between the name and their fields or variants. Use () when no properties are needed. The supported properties are #linear and #repr-c:

(#struct FileHandle (#linear) ((descriptor #u64)))
(#enum Maybe (#repr-c) ((Maybe.Some #u64) Maybe.None))
(#struct NativeOwner (#linear #repr-c) ((handle (#ptr #u8))))

Aggregates become linear transitively when they own a linear field or, for an enum, any linear payload in any variant. References do not make their containing aggregate linear because they do not own their referents. Explicit #linear forces a struct or enum to be linear even when all fields or payloads are plain data. It does not change layout or Send/Sync. Generated task state types use this property.

File references identify declarations directly, without copying source or prepending prefixes. Aliases give those declarations explicit local spellings:

(#alias read = ./shared.lim::read)
(#alias Widget = project::compat/lib.lim::Widget)

./ paths resolve relative to the source containing the reference. project:: paths resolve from the nearest lim.project ancestor of the principal source; when there is no manifest, its directory is the project root. All dependencies use that same root. / retains filesystem-absolute meaning. Rooted paths cannot contain ..; direct references do not search module-path lists. Files are loaded once by canonical identity, and alias cycles and runtime recursion are rejected.

A directory containing lib.lim establishes a library permission boundary. Each source belongs to its nearest boundary, including a separately compiled white-box test. References within that library may name implementation files; references from outside must target lib.lim and select an exported declaration. Nested library directories establish independent boundaries. Canonical paths prevent symlink and .. privacy bypasses. #unstable explicitly bypasses the entry-point/export restrictions for a selected declaration, not its struct fields.

Only lib.lim may contain (#export Type function ...), listing the declarations available outside the library. Other declarations remain library-internal. Exporting a struct type does not export its representation: external code cannot construct, read, write, borrow, or project its fields. Exporting an enum exposes every variant for construction and matching; individual variants cannot appear in #export. Every payload type must also be publicly accessible, including in unused variants. Adding a variant changes the exhaustive matching contract. An unexported enum remains private. To hide its representation, store it inside an exported opaque struct and expose functions that operate on that struct; see examples/opaque_handle.lim and examples/opaque_handle/lib.lim. Exported function signatures and aliases cannot expose private types. All implementation declarations remain visible to whole-program borrow checking and optimization.

Generated declarations belong to their invocation's library, not the physical .lim cache directory. Each generated file has access to its producer's definition library and its invocation library, including private functions, types, and representations. A nested generator gets its own definition library and the original invocation library; it does not accumulate its ancestors' definition-library privileges. A canonical file has one declaration identity, regardless of which alias reaches it. Separate source paths can carry different library versions.

Write @name to resolve a name before generator execution. Inside a generator definition it uses that definition's file scope; in supplied arguments it uses the invocation source's file scope. Qualification produces the actual flat file-qualified identifier (for example, /project/library/helper.lim::Helper), not a hidden binding or a runtime expression. Forwarding and substitution never qualify it again. Literal strings, generator parameters, and unmarked local bindings are not interpreted by this operation. Handwritten forward declarations are collected before qualification. Exported generated targets can be qualified using their library's literal export contract; other unknown names cannot be qualified. In particular, @local cannot silently become a local reference after splicing a literal function. Pass new declaration names as literal symbols.

Invocation references are checked using caller permissions before interpreting the generator, including explicitly qualified references inside quoted syntax. A caller cannot pass @lib@secret when that declaration is private to lib. Literal strings and selectors remain data: a generator may deliberately turn them into references using #gn-symbol, #gn-symbol-append, or #gn-variant. The resulting code uses its generated file's permissions. Thus generators are privileged library APIs: their authors must validate data and executable syntax they incorporate into their output. Qualification checks are not a sandbox for an arbitrary code-splicing generator. #unsafe obligations remain unchanged.

Inspectable generated files record permissions as reader syntax, for example:

(#generated-context
  ((producer "lib@make")
   (definition-module "/project/library/lib.lim")
   (definition-file "lib")
   (invocation-module "/project/app/lib.lim")
   (invocation-file "")))

This compiler-owned header is checked against the current generator and invocation on cache reuse. It contains no serialized source IDs or per-symbol permission comments. Copying a header into source, supplying one to a generator, or manufacturing one with generator operations is rejected. A generator cannot manufacture late @ qualification either: qualification is a source operation. Files outside a lib.lim boundary share the <global> module; physical invocation locations remain in the existing generated-file origin comments and do not prevent equivalent expansions in that module from sharing a cache artifact.

For example, an exported counter-reader generator can emit a call to a private counter-value helper. The consumer still cannot invoke that helper directly:

(#alias counter-reader = ./encapsulation/lib.lim::counter-reader)
(#generate counter-reader read-generated-counter)

See examples/generator_private_helpers.lim for a complete executable example.

An expansion instance includes the invoking file's identity, generator, and literal arguments. Identical calls in one file can reuse a generated declaration; calls in different files retain separate declaration identities. Cache keys also include resolved references, dependency contents, and validated definition/caller contexts. Multiple aliases to one source share that source; separate dependency versions occupy different source paths.

An exported generator may invoke its library-private generator helpers, including nested generators. Syntax equality and argument deduplication compare values, not the way symbols were constructed. Builtin expansions also distinguish producing definition contexts. Cache keys include definition/invocation context headers as well as generator/dependency identities, and digests cover the complete generated file. Cached authority is reconstructed from the current expansion, not accepted from a file's self-asserted claims. #std remains one compiler-provided prelude. Its facade explicitly lists its declarations; parameter labels retain their original source spelling. See examples/library_boundary.lim and examples/encapsulation/test.lim.

To bound compiler resource use, a project is limited to 128 simultaneously nested source files, 4096 unique source dependencies, and 64 MiB of cumulative source text (including the root file). Dependency-limit errors identify the reference that crosses the limit; an oversized root file is rejected before import traversal.

The compiler resolves each file reference exactly: ./ is relative to its source file, project:: is relative to the compilation's project root, and / is an absolute filesystem path. There is no fallback search through module directories.

Projects may add a lim.project manifest beside the root source:

schema-version = 1
name = "example"
source-root = "src"
output-dir = "build"
module-path = "modules"
target = "x86_64-sysv"
link-lib = "m"
link-object = "native/support.o"

Manifest paths are relative to the manifest. The nearest manifest above the principal source defines the project:: root, including for dependencies outside that directory. Without a manifest, the principal source's directory defines it. The CLI defaults binary output into the output directory and applies the manifest target unless --target overrides it. Repeated link-lib and link-object entries add linker inputs. Schema version 1 validates required name/version, supported target names, existing source and module directories, duplicate module roots, and existing object files; unknown keys are errors.

Lexical syntax

Whitespace separates tokens. // starts a line comment. A line beginning with bare # is also a comment unless the # begins a keyword, operator, or character literal.

The lexer recognizes:

  • ( and ) for lists;
  • { and } for named pair lists;
  • [ and ] for typed infix expressions;
  • = for record assignments and ; for entry/form termination;
  • 'form quote syntax;
  • #generate as the generated-code keyword; #generate stays inside identifiers;
  • symbols;
  • signed and unsigned integer literals;
  • floating-point literals;
  • strings and character literals.

. is an ordinary character in a symbol, not a namespace or member-access operator. - is also an ordinary symbol character. Thus these are single identifiers:

Work::poll
my-value
Choice.Ready

Builtin forms are distinguished by their # prefix:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #return 42u64;
}

The character literal syntax is #\a, #\space, #\newline, and so on. Unicode escapes use #\u{03bb}. Strings support \n, \r, \t, \\, \", and \u{...} escapes.

Integer literals may use binary, octal, hexadecimal, and underscores:

42u32  -1i8  0b1010u16  0o77u8  0xffffu128

Floating-point literals carry an explicit width when used in canonical code: 1.5f32 and 0.25f64.

Types

The builtin scalar types are:

Category Types
unsigned integers #u8, #u16, #u32, #u64, #u128, #usize
signed integers #i8, #i16, #i32, #i64, #i128, #isize
floating point #f32, #f64
other scalars #bool, #char
zero-sized ()
diverging !

Fixed aggregates are written explicitly:

(#tuple #u64 #bool #char)
(#array #u32 4)

Construct a fixed-size array value with #array-of, keeping it visually distinct from the #array type form:

(#let values (#array #u32 3)
  (#array-of (#array #u32 3) 10u32 20u32 30u32))

An immutable slice type is written (#slice T). Borrow an array directly with (#borrow-slice array), or select [start, end) with (#borrow-slice array start end). These operations explicitly borrow storage; they neither move the array nor allocate. Both bounds must be #usize. (#slice-of array-reference) instead converts an existing immutable array reference into a slice without extending its backing storage's lifetime. Use (#slice-len view) for its runtime length and (#slice-idx view index) to get a shared reference to an element. Indexing checks the index against the slice length and traps if it is out of bounds. Use (#slice-range view start end) to create an immutable half-open subrange [start, end). Both bounds are #usize; the operation traps if start > end or end > (#slice-len view). Empty and end-boundary ranges are valid. A subslice retains the original borrow provenance, including across function returns; it does not extend the referent's lifetime. Slices remain immutable.

User-defined names refer to concrete structs, enums, and aliases. Generic declarations and angle-bracket applications are not part of Lim. Generators create concrete specializations explicitly, such as (#generate #vec ((element #u64) (allocator Alloc) (name VecU64))). Allocator-backed collections add their concrete operations explicitly with (#generate #vec-alloc ((element #u64) (allocator Root) (vector VecU64) (destroy destroy))); Root::State must denote Alloc, the state type passed to #generate #vec. The root provides a byte-pointer allocation enum, safe ::allocate, and unsafe ::grow / ::deallocate; grow takes :old-layout and the requested :layout. Handwritten and generated bundles follow the same ordinary naming convention, without a producer requirement. #std provides SystemAllocator::Allocator, whose empty state is constructed with (#struct-literal SystemAllocator ()). Providers promise fresh, unique, aligned, non-null successful allocations, preservation of the old allocation on growth failure, and matching deallocation. Names and type checking cannot prove these semantic promises. The generated API includes VecU64::new, ::reserve, ::push, ::get, ::get-mut, ::set, ::pop, and ::free. (#generate #vec-sort ((element #u64) (vector VecU64) (comparator compare-u64))) adds VecU64::sort; its named comparator accepts two immutable element references and returns #bool. Allocation failure and capacity overflow are returned in generated result types. See the allocator ABI for the allocator and destruction function signatures.

() is the unit value and ! is the never type. A function returning ! must not reach a normal return. A void function returns explicitly with (#return ()).

Heap-owned UTF-8 strings

Import library/string.lim for the concrete, opaque, linear String type. String literals remain fixed character arrays; conversion is explicit. The native Lim process allocator owns the bytes. It pools small allocations and uses Linux memory-mapping syscalls for backing storage, without libc or FFI. This is an ordinary library, not a new builtin or an implicit allocation.

(#std)

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let text (#array #char 3) "Aé🙂";
    #return:
      #match
        (String::from-chars { text = (#borrow-slice text); })
        (#case
          (StringCreateResult.StringCreated owned)
          (#block
            (#let length #usize (String::len { string = (#borrow owned); }))
            (String::free { string = owned; })
            (#if [#usize; length == 7usize] 42u64 1u64)))
        (#case (StringCreateResult.StringCreateFailed error) 2u64)
}

String::new creates an empty string without allocating. String::with-capacity, String::from-chars, String::from-utf8, and String::try-clone return StringCreateResult: StringCreated contains an owned string; StringCreateFailed contains a StringError. Cloning is an explicit, fallible deep copy, never a shallow #clone of the allocation handle.

String::len and String::capacity take ((string (#ref String))) and count bytes, not characters. String::is-empty uses the same shared argument. String::reserve takes ((string (#ref-mut String)) (additional #usize)); additional capacity is relative to the current length. String::push-char, String::push-chars, and String::push-utf8 take a mutable string and, respectively, : value #char, : text (#slice #char), or : bytes (#slice #u8). These operations return StringStatus: StringOk or (StringErr error). Validation, overflow, and allocation failures leave the original string unchanged. Errors are StringOutOfMemory, StringCapacityOverflow, StringInvalidUtf8, and StringInvalidChar. String::push-string ((string (#ref-mut String)) (text (#ref String))) appends the borrowed source string and returns the same StringStatus. It does not consume either string; the source remains available after the call.

With #std, the embedded String module can be used without an explicit import. This example builds a string from fixed character arrays, appends a second owned string by shared borrow, and releases both owners:

(#std)

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let greeting (#array #char 5) "Hello";
    #let suffix (#array #char 9) ", world 🙂";
    #let-mut message String:
      #match
        (String::from-chars { text = (#borrow-slice greeting); })
        (#case (StringCreateResult.StringCreated created-message) created-message)
        (#case (StringCreateResult.StringCreateFailed error) (#panic))
    #let tail String:
      #match
        (String::from-chars { text = (#borrow-slice suffix); })
        (#case (StringCreateResult.StringCreated created-tail) created-tail)
        (#case (StringCreateResult.StringCreateFailed error) (#panic))
    #assert:
      #match
        (String::push-string { string = (#borrow-mut message); text = (#borrow tail); })
        (#case StringStatus.StringOk true)
        (#case _ false)
    #assert:
      #match
        (String::push-char { string = (#borrow-mut message); value = #\!; })
        (#case StringStatus.StringOk true)
        (#case _ false)
    #assert [#i64; (#println (#borrow message)) == 0i64];
    String::free { string = tail; };
    String::free { string = message; };
    #return 42u64;
}

String::byte-at takes a shared string and an index parameter of type #usize. It returns (StringByte byte) with a copied #u8, or StringByteOutOfBounds. String::bytes ((string (#ref String))) returns an opaque StringBytes view that retains the owner borrow, preventing mutation, moving, or freeing its owner while the view is live. StringBytes::len ((bytes view)) and StringBytes::byte-at ((bytes view) (index #usize)) inspect that view without allocating; indexing also returns a copied byte. No mutable byte access is exposed: safe operations preserve valid UTF-8. String::data-pointer ((string (#ref String))) is an unsafe raw-I/O escape returning (#ptr-mut #u8). The pointer does not retain the owner borrow. The caller must keep a shared borrow alive, read only initialized bytes, and never write, grow, move, or free the string while using it. Safe stdout functions uphold these obligations internally; printing does not require #unsafe.

Borrowed UTF-8 views

(#std) also provides StringView and Utf8Slice: opaque, allocation-free UTF-8 views that retain a shared borrow of their source. String::view ((string (#ref String))) borrows the complete String in constant time, since safe String operations already guarantee valid UTF-8. Utf8Slice::from-owner ((owner (#slice #u8))) validates the complete byte slice and returns (Utf8Slice::Result.Valid view) or Utf8Slice::Result.InvalidUtf8, without allocating or copying the bytes. Empty input and embedded NUL are valid.

Both APIs come from an ordinary library generator. To declare another concrete view, choose its public name and source layout explicitly:

(#std)

#generate #utf8-view { name = BorrowedText; owner = (#slice #u8); }

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let bytes (#array #u8 2): #array-of (#array #u8 2) 195u8 169u8;
    #let view BorrowedText:
      #match
        (BorrowedText::from-owner { owner = (#borrow-slice bytes); })
        (#case (BorrowedText::Result.Valid accepted) accepted)
        (#case _ (#panic))
    #let-mut iterator BorrowedText::Chars: BorrowedText::chars { view = view; };
    #assert:
      #match
        (BorrowedText::Chars::next { iterator = (#borrow-mut iterator); })
        (#case (BorrowedText::CharResult.Char value) (#char::eq value #\é))
        (#case _ false)
    #forget iterator;
    #return 42u64;
}

For a generated name V, the public operations are:

Function Arguments Result
V::from-owner ((owner OwnerType)) with the declared source type V::Result: (V::Result.Valid view) or V::Result.InvalidUtf8; validates in O(bytes).
V::len ((view (#ref V))) #usize byte length, not character count.
V::is-empty ((view (#ref V))) #bool.
V::byte-at ((view (#ref V)) (index #usize)) (Utf8Byte copied-byte) or Utf8ByteOutOfBounds.
V::boundary ((view (#ref V)) (index #usize)) Whether the offset is a scalar boundary; zero and length are boundaries, out-of-range is false.
V::subview ((view (#ref V)) (start #usize) (end #usize)) V::Result for half-open byte range [start,end): (V::Result.Valid subview), V::Result.InvalidRange, or V::Result.InvalidBoundary.
V::clone ((view (#ref V))) A new borrowed view; copies only borrow metadata, not the source or allocation.
V::chars ((view V)) V::Chars, consuming the view and retaining its source borrow.
V::Chars::next ((iterator (#ref-mut V::Chars))) (V::CharResult.Char scalar) or V::CharResult.End; repeated end reads remain at end.

Subview bounds are checked before additions or byte access, including maximal #usize offsets. Splitting a multibyte scalar is an error, including an empty range at a non-boundary offset. Nested subviews use offsets relative to their parent and retain the original source borrow, not the temporary parent view. Views can be returned through helpers or stored in aggregates. Forgetting a parent does not release a child's or iterator's source loan. Mutation, growth, moving, and destruction of that source are rejected while such loans remain live. Explicitly #forget unused views and iterators; no destructor or allocator operation runs. See examples/string_view.lim for an owned String example.

Iteration decodes Unicode scalar values, not grapheme clusters or normalized text. It requires no dynamic dispatch, function pointers, heap allocation, or compiler-specific view primitive. Generated ordinary Lim is inspectable in .lim/generated/ and uses the same content-addressed cache as other generators. The supporting V-byte, V-valid, and V-decode functions perform checked byte access, validation, and decoding; V-decode asserts an in-range scalar boundary and returns (#tuple #char #usize) containing the scalar and its byte width. V-assume-valid is an unsafe constructor that skips validation. Its caller must prove the complete source is valid UTF-8 and preserve the source's shared borrow. The safe String-view wrapper upholds this contract internally.

The generator accepts only (#ref String) and (#slice #u8) sources. Arbitrary reader callbacks could change interior-mutable storage after validation and are not accepted. Packed String bytes and Lim word-backed byte slices use separate accessors: no raw pointer is reinterpreted as a word-layout slice or reference.

Raw-backed scalar references preserve exact byte addresses and access the native width of the scalar, including at odd #u8 addresses. References keep internal high-bit storage metadata, which is removed before syscall and assembly pointer operands. Lim aggregates and arrays still use Lim's word layout; raw borrowing does not turn them into packed C aggregates. Unsafe pointer-to-reference conversion still requires valid storage, alignment, lifetime, and exclusive-access proofs from its caller. String-pop-char takes a mutable string and returns (StringPopped character) or StringEmpty. String-clear takes a mutable string, empties it, and retains its capacity. Strings need not be NUL-terminated and may contain embedded NUL bytes.

String-free ((string owned)) consumes the owner and releases its allocation. Every owned string must be consumed, returned, or explicitly forgotten before returning; references do not implicitly destroy it. See the system allocator contract and the runnable printing example.

Top-level declarations

Predicate contracts and constrained types

Lim tracks evidence for named, pure Boolean functions and typed scalar comparisons. It does not solve predicates, infer implications, or symbolically execute their bodies. Predicate identity and argument identity must match. Multiple requirements have AND semantics; a #bool::and conjunction supplies its individual facts.

#fn below-100 {
  #params = { value = #u64; };
  #returns = #bool;
  #body:
    #return [#u64; value < 100u64];
}

#fn submit {
  #params = { value = #u64; };
  #returns = ();
  #requires: (below-100 { value = value; });
  #body:
    #return ();
}

#fn validate-and-submit {
  #params = { value = #u64; };
  #returns = ();
  #body:
    #if-valid (below-100 { value = value; }): submit { value = value; };
    #return ();
}

#if-valid executes an ordinary Boolean expression and grants the evidence carried by its successful branch. An ordinary #if grants no new evidence. At a branch join, only evidence available on every continuing path survives. A saved predicate result can carry evidence, but a later write to a dependency revokes that evidence even if the saved Boolean remains true.

Place contract clauses first in a function body:

Clause Caller rule Function rule
(#requires P) Must already have evidence for P P is available on entry
(#ensures Q) Receives Q after normal return Programmer promises Q; checked dynamically when instrumented
(#preserves P) P survives if it was available before the call Conditional promise: entry P implies exit P

A validator is an ordinary function without the requirement it tests. Every intermediary must explicitly annotate the requirements and guarantees it exports. Only structural read/write footprints propagate through calls; semantic contracts are never inferred from callees. Consequently, writes to an unread sibling field need not revoke a predicate, but a wrapper that changes a predicate's inputs must declare its own #preserves or #ensures.

(#result) names the result in #ensures. (#old observation) snapshots an entry observation for a postcondition. Snapshot scalar observations rather than reference/slice handles. These forms are unavailable in requirements, preservation clauses, validation bodies, or assumptions. A mutable value parameter is a local copy: postconditions must use scalar #old observations or the returned value instead of promising properties of its final binding.

(#assume P) explicitly trusts P without evaluating the predicate or any of its arguments, including in instrumented builds. It still checks predicate purity, argument types, identity and dependencies. It grants no exception to ordinary type, ownership, initialization or borrowing rules. Assumptions do not suppress independent runtime checks of function contracts.

A constrained type has the same runtime representation as its base type:

#fn below-100 {
  #params = { value = #u64; };
  #returns = #bool;
  #body:
    #return [#u64; value < 100u64];
}

(#type Small (#where (value #u64) (below-100 { value = value; })))

(#struct Request () { count = Small; tag = #u64; })

#fn consume-small {
  #params = { value = Small; };
  #returns = ();
  #body:
    #return ();
}

#where can appear directly wherever a supported type is accepted, or behind a type alias. Its binder is local to its predicates. Construction and assignment require existing evidence; they do not silently rerun predicates. Explicitly constrained parameter/result types declare the corresponding entry/exit requirements. Plain base types declare none.

A temporary branch fact may be discarded after mutation. Fixed constraints on storage must instead be restored before an exclusive borrow returns access to its owner. A raw mutable reference can temporarily violate an invariant inside its exclusive lifetime. The compiler requires fresh validation, a declared postcondition/preservation promise, or an explicit #assume before the owner becomes available again. After the mutable reference's last use, a base-input predicate can inspect the frozen owner to close this obligation. Aliases and returned mutable references retain the restoration obligation.

#index-proven accesses a referenced fixed array using an explicit bounds claim. Its index must have type #usize, and the exact fact (#usize::lt index N) must be available for the array's length N. A smaller bound or a named predicate with the same body does not supply that fact. Programmer-written helpers connect claims through their declared contracts:

#fn under-two {
  #params = { index = #usize; };
  #returns = #bool;
  #body:
    #return [#usize; index < 2usize];
}

#fn widen {
  #params = { index = #usize; };
  #returns = ();
  #requires: (under-two { index = index; });
  #ensures: [#usize; index < 4usize];
  #body:
    #return ();
}

(#type Index4 (#where (index #usize) [#usize; index < 4usize]))

#fn read-four {
  #params = { values = (#ref (#array #u64 4)); index = Index4; };
  #returns = #u64;
  #body:
    #return: #index-proven values index;
}

#fn use {
  #params = { values = (#ref (#array #u64 4)); index = #usize; };
  #returns = #u64;
  #body:
    #return:
      #if-valid
        (under-two { index = index; })
        (#block
          (widen { index = index; })
          (#let checked Index4 index)
          (read-four { values = values; index = checked; }))
        0u64
}

Removing the helper call rejects the assignment and subsequent access. Helpers are ordinary functions; their #ensures remain programmer promises. Typed comparisons are opaque facts: operand order, scalar type and value identity must match. The checker performs no arithmetic implication search. #if-valid may validate the exact comparison directly, and #assume may explicitly supply it without evaluation.

Production #index-proven emits no array bounds check. Instrumented builds retain an independent bounds check at the access, including after an assumption. Ordinary #index remains a checked operation. Both forms retain ordinary borrow, initialization and ownership checks; proven indexing also supports element borrows. Dynamic slices continue using their existing checked operations.

Compile tests with lim --check-contracts ... (equivalently --cfg contracts=check). Instrumentation checks requirements on entry, postconditions on each normal return and preservation only when the predicate was initially true. Production compilation omits these additional assertions, snapshots and proof objects. Actual #if-valid branches remain executable. Dynamic checks test implementations; they are not a universal proof of a programmer's promises.

Predicate functions must have stable reads and no effects or hidden mutable global dependencies. Unknown indirect reads/writes are handled conservatively. Unsupported constrained container shapes and exhausted analysis budgets are errors, never silently weakened guarantees. See program verification for implementation boundaries.

Functions

Functions are always free-standing; Lim has no methods or impl blocks. The canonical form is:

(#fn add ((left #u32) (right #u32)) #u32
  (#let total #u32 (#u32::add-wrap left right))
  (#return total))

The parameter list is a list of (name Type) pairs. Function records also accept a parameter record such as { left = #u32; right = #u32; }:

#fn add {
  #params = { left = #u32; right = #u32; };
  #returns = #u32;
  #body:
    #return [#u32 #wrap; left + right];
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #return: #as (add { right = 2u32; left = 40u32; }) #u64;
}

Colon grouping is ordinary parenthesis sugar, independent of named arguments:

(#return : #u64::add-wrap left right)
// Equivalent to (#return (#u64::add-wrap left right)).

(a : b : c)
// Equivalent to (a (b (c))).

The old sibling notation (: left 1 : right 2) now nests and is not a named argument table. Write ((left 1) (right 2)) or { left = 1; right = 2; } instead. Empty lists use (). Nested explicit delimiters contain their own syntax. A colon must have syntax on its line or a nonempty indented group. Pipeline::Pending, left:right, and :label remain flat identifiers. Parameters may be marked mutable:

#fn increment {
  #params = ((#mut value #u64));
  #returns = #u64;
  #body:
    #set value [#u64 #wrap; value + 1u64];
    #return value;
}

Function calls name every argument explicitly. Safe calls use a function name followed by a record or a list of (name value) pairs. Unsafe and external functions use #unsafe-call within #unsafe. Each argument label must match a parameter in the declaration:

(add ((left 20u32) (right 22u32)))
add { left = 20u32; right = 22u32; }

When a variable has the same name as its parameter, ($ name) expands to (name name):

#fn add {
  #params = { left = #u32; right = #u32; };
  #returns = #u32;
  #body:
    #return [#u32 #wrap; left + right];
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let left #u32 20u32;
    #let right #u32 22u32;
    #return: #as (add (($ left) ($ right))) #u64;
}

This is general parser sugar, so it also works in struct field lists and quoted generator syntax. It accepts one identifier or an explicit unary borrow of one identifier: ($ (#borrow owner)) expands to (owner (#borrow owner)). The same form supports #borrow-mut, #pin-borrow, and #pin-borrow-mut; arbitrary expressions and implicit borrowing are not supported. It preserves that identifier's source location for diagnostics, and does not change evaluation order or borrowing rules. The formatter preserves the shorthand spelling. Do not add extra groups around an already grouped ($ name) pair: ((($ name))) would introduce an extra list, just like (((name name))).

Positional call forms are rejected. Calls with no arguments use function {} or (function ()) for safe functions, or (#unsafe (#unsafe-call function ())) for unsafe and external functions. The equivalent empty colon group () formats as (). Ordinary calls reject unsafe and external callees even inside #unsafe; #unsafe-call requires an enclosing #unsafe block and rejects safe callees. The explicit #call form remains accepted for existing canonical generator output; handwritten calls do not need it. Both forms accept ($ name) shorthand and apply the same argument checks.

(#call-graph) returns a (#slice #char) containing the actual caller chain: main:21 -> second:17 -> third:13. Every number is the executing line inside that function: the call to the next function, or the final #call-graph expression. Repeated calls on different lines are distinguishable. No file paths are included; function names remain directly greppable.

The trace uses bounded stack storage, without implicit heap allocation or global mutable state. Its view cannot outlive the current function. Copy it explicitly with String::from-chars when an owned result is needed; see examples/call_graph.lim for printing and freeing that string. Only functions that can reach a trace carry caller context; thread spawning transfers its own owned context into the worker.

Named argument expressions are evaluated exactly once in their written order at the call site. Labels select parameter slots without rearranging effects. Each expression finishes before the next begins, and the callee starts only after every argument is ready. A non-returning earlier argument prevents later arguments and the callee from running. The checker accounts for moves, loans and evidence changes in that sequence; requirements apply at the actual call. #struct-literal field values also execute in written order, while declaration order continues to determine representation and positional patterns. Aliases, direct file calls, callable scalar intrinsics, generated code and async suspension follow the same rule for supported forms.

Compatibility: earlier experimental compilers evaluated named arguments and struct initializers in declaration order. Effectful reordered values can now behave differently. Name/arity validation remains static, before execution.

Generic function declarations and angle-bracket calls are rejected. Use a generator to emit a concrete function for each required type combination.

There are no implicit returns. Every reachable function path must use #return; a unit return must use (#return ()).

Native functions declare their calling convention explicitly. #abi-c selects the target's C ABI; external signatures currently accept scalar values and raw pointers only. By-value aggregate FFI signatures remain rejected. Calls are unsafe FFI boundaries and must use #unsafe-call inside #unsafe:

(#extern-fn #abi-c abs ((value #i32)) #i32)

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #return: #as (#unsafe (#unsafe-call abs { value = -42i32; })) #u64;
}

Binary compilation links statically without libc or pthread when the assembled objects have no unresolved symbols and no libraries were explicitly requested. Foreign references still require the runtime linking path; generated threads do not. Additional native link inputs can be supplied repeatedly with --link-lib NAME and --link-object PATH. The internal linker reads object definitions and relocations, resolves requested shared libraries, and reports missing libraries or symbols before publishing output. These options apply to binary output, not --emit-asm.

(#std) is an explicit top-level opt-in to Lim's bundled standard modules, including String and standard output. Their immutable source is embedded in the compiler, so this works outside a source checkout. Without #std, these names are not added to the program. (#println (#borrow string)) writes the UTF-8 bytes of a borrowed String, then a newline, and returns #i64: zero on success or a negative errno on failure. It neither converts string literals implicitly nor consumes the string. Output can be partial on failure, and the newline is skipped when writing the string bytes fails. See examples/string_println.lim for building and printing a string.

std-read-line ((string (#ref-mut String))) explicitly appends a UTF-8 line from stdin to an existing String. StdLineRead usize reports appended bytes (excluding the consumed LF); StdEndOfInput reports EOF before any new text. StdReadFailed StdReadError distinguishes StdIoError i64 (negative errno) from StdTextError StringError (invalid UTF-8 or allocation failure). Existing text and successfully appended complete characters remain intact on failure. EOF after a partial line returns that line normally; interrupted reads retry. This API is included in #std. See the input contract and examples/string_stdin.lim for an echo loop with explicit cleanup.

examples/echo_input.lim shows byte-at-a-time input and output using Linux x86-64 read and write syscalls inside unsafe #asm blocks; tests/io_examples.rs runs it with piped input and checks that stdout matches. To try it yourself:

printf 'hello from Lim\n' | ./target/debug/lim examples/echo_input.lim -o /tmp/lim-echo
printf 'hello from Lim\n' | /tmp/lim-echo

The program writes every byte it reads back to standard output, stopping at end-of-file. The example is target-specific and uses #cfg when the standard library has multiple platform implementations. library/linux_x86_64.lim also wraps process identity/group queries, descriptor operations, memory mapping, clocks, sleeping, and random-byte generation. These wrappers expose the kernel's raw result convention: successful values are returned directly, and errors are negative errno values. The integration test exercises both successful calls and deterministic invalid-descriptor errors. Other syscalls can be issued explicitly with #linux-syscall inside #unsafe. Importing library/linux_x86_64.lim also imports the complete native x86-64 syscall number catalog in library/linux_x86_64_syscall_numbers.lim; it names the Linux common and native 64 ABI entries while excluding x32.

C aggregate layout

#repr-c opts a struct or enum into the x86-64 System V C layout for layout queries only; it does not change the Lim runtime representation or grant FFI compatibility. Struct fields follow declaration order, with natural field alignment and tail padding. #size-of and #align-of report this layout for marked types; #offset-of Type field reports a marked struct field's byte offset. Payload enums use a signed 32-bit C int tag followed by a maximally sized and aligned union of variant payload structs; fieldless enums use the same 32-bit tag. Discriminants must fit in signed 32-bit C int. These guarantees currently apply to layout queries only: Lim's runtime aggregate storage still uses its internal flattened representation, so #repr-c values must not be reinterpreted as C memory or passed through FFI. #size-of, #align-of, and #offset-of report a C layout description, not the in-memory layout of a Lim value. By-value aggregate FFI and field access through external aggregate pointers remain rejected. Only the native x86-64 System V target is currently supported.

Type aliases

(#type UserId #u64)
(#type Pair (#tuple #u64 #bool))
(#type Matrix (#array #f32 4))

Aliases are concrete. Recursive aliases are rejected.

Structs

Structs are value types with named fields:

(#struct Point () { x = #u64; y = #u64; })

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let point Point: #struct-literal Point { x = 7u64; y = 9u64; };
    #return: #get point y;
}

Use a generator to emit concrete struct declarations when a family of structs is needed.

Enums

Variants may be fieldless or carry one payload. Use a named struct when a variant needs multiple fields:

(#struct MovePayload () { x = #i32; y = #i32; })
(#enum Message () (Message.Quit (Message.Move MovePayload) (Message.Write (#array #char 8))))

Discriminants are assigned from zero, or can be explicitly supplied using a numeric value after the variant name. Variant names are global within a program and must be unique.

Native #match dispatch uses a bounds-checked jump table for enums with 4–4096 contiguous discriminants when at least four distinct arms are initial targets. Explicit nonzero and full-width tags are supported; declaration and arm order need not follow tag order. Entries are signed 32-bit offsets in read-only storage, resolved by Lim's own linker. Invalid tags trap before indexing the table. Guards and refutable payload patterns retain their ordered fallback checks. Small or sparse enums, matches with few destinations, and or-patterns keep direct comparison chains. This changes no language semantics, and whole-program stack analysis follows every table target. See examples/enum_dispatch.lim for a runnable payload-dispatch example.

To inspect an enum without extracting its owner or payload, use (#variant-is reference Variant). It works through ordinary and pinned, shared and exclusive references. The reference is evaluated once; only the discriminant is read. The test grants no permission to move a payload or ignore a live loan. Later payload projections still check the active variant at runtime. See examples/variant_is.lim for inspection of a linear owner followed by explicit consumption.

Globals and statics

Top-level #const/#let values are immutable compile-time values. #static creates immutable storage and is useful for aggregate data. Ordinary statics are placed in read-only memory; statics containing atomic fields use writable memory so their explicit interior-mutability operations can run. Every read of a static must occur inside #unsafe, including reads used to create a reference to it:

(#const answer #u64 42u64)

(#static values (#array #u64 3) (#array (#array #u64 3) 10u64 20u64 30u64))

#fn first-value {
  #params = {};
  #returns = #u64;
  #body:
    #return: #unsafe (#index values 0u64);
}

Initializers must be compile-time values. Constant references, arithmetic, casts, conditionals, tuples, arrays, structs, enums, and floating-point values are supported. Cyclic constant references are rejected.

Atomic initializers may also be constant, including inside structs, tuples, arrays and enum payloads. They do not execute runtime initialization functions:

(#static counter (#atomic #u64) (#atomic-init #u64 0u64))

#fn increment-counter {
  #params = {};
  #returns = #u64;
  #body:
    #return: #unsafe (#atomic-fetch-add (#borrow counter) 1u64 #memory-relaxed);
}

This does not permit an ordinary mutable borrow of a static, even inside #unsafe; updates go through the atomic API. A future may receive a reference to static or heap storage through an explicit parameter and select it against a local reference. Direct pinned static field/tuple borrows inside a future also preserve their global storage identity. General direct local/static ordinary-reference selection still requires a checked boundary parameter; unsupported combinations fail closed rather than receiving fabricated anchors.

Variables and mutation

Local bindings always state their type:

(#let count #u32 0u32)
(#let-mut total #u64 0u64)

#let creates an immutable binding; use #let-mut for a mutable binding. Bindings may not shadow a visible parameter, local, or global; choose a distinct name instead. Names may be reused in separate sibling scopes when neither binding is visible from the other. #set assigns a mutable scalar or aggregate local:

(#set total (#u64::add-wrap total 1u64))

A whole reference-bearing local may also be assigned from another typed binding or a fieldless enum variant, for example (#set view next) or (#set view Empty). The replacement installs that binding's reference origins and releases the old binding's loans. Shared references remain Copy; exclusive references transfer without duplication. An outstanding borrow of the destination still prevents replacement, and a linear old value must already have been consumed. Arbitrary reference-bearing RHS expressions and member replacement retain their existing restrictions. examples/reference_assignment.lim releases the old owner, reads the new owner, then drops both shared handles before mutating the new owner.

Binding an exclusive reference, or storing it in an aggregate, transfers its handle: subsequent use of the source handle is rejected. Extracting an exclusive reference from an owned aggregate likewise transfers its selected slot, not the pointee or the other fields. Forgetting the remaining container does not end the transferred borrow; explicitly release the destination handle before mutating its owner. See examples/exclusive_reference_move.lim. References need no mandatory destruction at function exit, and passing a reference directly to a function is a call-duration reborrow rather than a handle transfer.

A derived field reference also suspends overlapping parent access through function calls. Moving the child into another aggregate, or moving and restoring its holder through pinned storage, does not erase that restriction. Calls may use the child's own reference; explicitly release the child holder before lending the parent again. examples/reference_parent_call.lim demonstrates that order, and tests/ui/call-suspended-parent.lim shows a rejected parent call.

The same access restriction applies when a function returns the child reference, directly or inside an aggregate. A returned call reborrow retains the referent's loan even if its temporary parent handle is released; it does not require that handle's storage to stay alive. See examples/returned_reference_parent.lim for a returned reference carried out of a labeled loop and used after parent-handle cleanup. tests/ui/call-returned-parent.lim rejects lending the parent again while its returned child is live.

Struct types are not constructors. Create a value with #struct-literal, or write a named free-standing constructor function that returns one. Every field must be supplied exactly once; fields may appear in any order, and omitted fields are not defaulted:

(#struct Point () { x = #u64; y = #u64; })
(#let point Point (#struct-literal Point { y = 22u64; x = 20u64; }))

Unknown, duplicate, or missing fields are compile-time errors. A type name in call position, such as (Point 20u64 22u64), is rejected; give constructor functions distinct names such as make-point. The UI suite covers this rejection in tests/ui/type-as-constructor.lim; it also pins the diagnostic spans for positional calls, generic function declarations, and angle-bracket generic call syntax in tests/ui/positional-call.lim, tests/ui/generic-function.lim, and tests/ui/generic-angle-call.lim.

Aggregate projections can be updated with #set-index, #set-field, and #set-payload:

(#set-index values 0u64 10u64)
(#set-field point x 11u64)
(#set-field pair 1 12u64)
(#set-payload choice Move 0 5i32)

Mutable slices use a separate type and constructors: (#slice-mut #u64), #borrow-slice-mut array to borrow a full mutable array, or #borrow-slice-mut array start end to select a half-open range. #slice-mut-of converts an existing mutable array reference, #slice-mut-idx provides exclusive element access, and #slice-mut-split view at to consume a view and produce two disjoint halves. The split point is a checked #usize index; an index greater than the length traps, and the halves cover [0, at) and [at, len). Views are linear: splitting consumes the parent, and overlapping mutable loans or access through the original array are rejected while a view is live. Each half must itself be consumed (for example, passed to a function or explicitly #forget-ted). Mutable slices can be returned when their inferred provenance comes from a function argument; a view of a local array cannot escape.

(#borrow (#deref reference)) and (#borrow-mut (#deref reference)) explicitly reborrow the existing referent without loading or moving it. Exclusive reborrowing requires an exclusive parent. A pinned parent produces a pinned reborrow; this syntax cannot remove the pin guarantee. Scoped borrow forms accept the same dereferenced places.

Pinning a mutable slice holder does not pin its backing elements. An exclusive reference to that holder, including (#pin-ref-mut (#slice-mut T)), can reborrow a range through (#slice-mut-range (#deref holder) start end) without extracting or moving the holder. A shared holder reference cannot grant this exclusive access. The resulting range still borrows the original backing storage and must end before conflicting access to that storage.

(#slice-mut-range parent start end) reborrows an existing mutable slice handle: a named handle or an exclusive, variable-rooted aggregate field/tuple slot such as (#get holder view). Owned aggregate projections require a mutable owner; projections through a shared reference and temporary receiver expressions are rejected. It does not consume the parent. Parent access, transfer and destruction are suspended until the child is released. Nested views retain the original backing storage's lifetime and physical offsets. Unrelated aggregate slots remain usable while a field's child is live. All range constructors check start <= end <= length and trap on failure; empty ranges are valid. Constant disjoint regions permit independent exclusive borrows (or an exclusive and a shared borrow). Dynamic bounds are conservatively overlapping; use #slice-mut-split for two runtime-disjoint mutable regions. Direct array borrowing accepts owned array places and array fields through ordinary references; it does not silently convert an array reference or erase a pinned reference.

(#let-mut values (#array #u64 4) (#array (#array #u64 4) 1u64 2u64 3u64 4u64))
(#let whole (#slice-mut #u64) (#borrow-slice-mut values))
(#let (#tuple left right)
  (#tuple (#slice-mut #u64) (#slice-mut #u64))
  (#slice-mut-split whole 2usize))
(#deref-set (#slice-mut-idx left 0usize) 17u64)
(#deref-set (#slice-mut-idx right 0usize) 25u64)
(#forget left)
(#forget right)

Explicit enum construction

#enum-literal marks value construction, just as #struct-literal does for structs. The variant declaration determines the concrete enum and payload type; this does not introduce type inference. A payload expression is evaluated once. A fieldless variant has no payload argument, while a variant carrying unit explicitly receives ().

(#enum Answer () ((Answer.Value #u64) Answer.Empty))

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let answer Answer: #enum-literal Answer.Value 42u64;
    #return: #match answer (#case (Answer.Value value) value) (#case Answer.Empty 0u64);
}

Patterns do not use the construction keyword: (Answer::Value value) binds the payload, and Answer::Empty tests the fieldless variant.

Local destructuring and #let-else support tuples, arrays, structs, and enum patterns. The else body must diverge, for example with #return, #break, or #panic.

For a named enum variant, omit the redundant enum annotation and explicitly delimit the failure body with #else:

(#enum Outcome () ((Outcome.Success #u64) Outcome.Failure))

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-else (Outcome.Success answer) (Outcome.Success 42u64): #else (#return 0u64);
    #return answer;
}

The named variant determines its declared owning enum; the value must have that type. This is declaration lookup, not inference from the value. The value is evaluated exactly once; use #block for a multi-statement computation. Success bindings become available only after the statement, never inside #else. Every failure path must return, break/continue an enclosing loop, or otherwise diverge. Exiting a loop created inside #else is not sufficient: it must be impossible to reach the following statement on failure.

(#std) provides #generate #enum-project, a generator rather than a runtime projection keyword. It accepts ((enum Enum) (variant Variant) (payload Payload) (mode ReferenceMode) (name Name)) and emits Name::Some/Name::None plus exactly one function, Name::project. The required mode is #ref, #ref-mut, #pin-ref, or #pin-ref-mut. Both the function's source parameter and its optional payload use that reference mode, around Enum and Payload respectively. Its ordinary safe #match body uses #case-ref, #case-ref-mut, #case-pin, or #case-pin-mut and returns None on a different variant. No allocation, payload move, unchecked projection, or asserting getter is involved. The optional reference retains its owner's loan through ordinary #let-else:

(#std)

(#enum Task () ((Task.Work #u64) Task.Idle))

#generate #enum-project {
  enum = Task;
  variant = Task.Work;
  payload = #u64;
  mode = #pin-ref-mut;
  name = WorkProjection;
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut task Task: Task.Work 42u64;
    #let-else (WorkProjection.Some frame) (WorkProjection::project { source = (#pin-borrow-mut task); }):
      #else (#forget task) (#return 0u64)
    #let answer #u64: #unsafe (#pin-read frame);
    #forget frame;
    #forget task;
    #return answer;
}

Destructuring consumes the aggregate and transfers each reference field's borrow provenance to its corresponding binding. Nested struct, tuple, array, and enum payload bindings retain their source loans; mutable fields cannot alias an already active mutable loan. Returning a destructured reference is allowed only when its origin outlives the function.

For borrowed fieldless tests, ignored payloads, or multiple borrowed failure patterns, use ordinary borrowed #match cases directly. Projection helpers require a payload-bearing variant with a referenceable payload type (not unit or #never). Named exclusive input handles must be explicitly reborrowed if they will be reused: (#pin-borrow-mut (#deref parent)) or (#borrow-mut (#deref parent)). There is no implicit reborrow in #let-else. On a projection mismatch the optional contains no reference, allowing cleanup of the owner in the failure branch. Another projection can be called there to inspect a different variant. Unsafe unchecked payload projections remain available only when the caller separately proves the active variant and initialization; there is no asserting pinned-payload getter.

Linear values and explicit cloning

Local values and function parameters are linear unless their type is plain-old data or a reference. Built-in scalar values, raw pointers, and structs, enums, tuples, or arrays whose fields/elements are all copyable are structurally Copy; they can be used without consuming the binding. Resource-bearing aggregates remain linear and must be consumed exactly once. A moved value cannot be read or cloned again. Use #clone at the point where an additional value is intended:

(#let count #u64 40u64)
(#let total #u64 [#u64 #wrap; (#clone count) + count])

Assignments reinitialize mutable bindings only after the previous linear value has been consumed. This also applies to linear struct fields, tuple slots, enum payloads, and array elements: consume the old member before replacing it. Replacing an aggregate member requires consuming all its linear leaves. Copy members can be overwritten directly, even inside a linear owner. An unknown array index cannot establish that a previously consumed element is the element being replaced; use a constant index for checked linear updates. examples/linear_field_replacement.lim demonstrates explicit consumption and replacement of a resource-bearing field and returns 42. A common update pattern moves the old value into the update and installs the replacement:

(#let-mut count #u64 0u64)
(#set count [#u64 #wrap; count + 1u64])

Loop conditions run repeatedly; any outer value they inspect must be explicitly cloned so it remains available on the next iteration. Both sides of a branch are checked, and a value moved on either path is unavailable after the join. #clone cannot duplicate mutable references or thread-task handles. If a function named <Type>-clone exists with signature (<Type>) -> <Type>, #clone dispatches to it; use that function to define deep-copy behavior for resource-owning types. Otherwise the backend clones the value representation. Every function return checks that all still-live linear bindings have been consumed. Pass an owned value to another function, or explicitly consume it with #forget. #forget does not run cleanup; it is intended for use after a user-written destruction function has released a value's resources. For example:

(#struct Buffer () ((allocation Allocation)))
(#fn Buffer::destroy ((buffer Buffer)) ()
  (Allocation::release (#get buffer allocation))
  (#forget buffer)
  (#return ()))

Destruction is an ordinary explicit call, not a type hook. A destructor takes the owned value by value, destructures resource-bearing fields, and calls the appropriate field destructors before forgetting any remaining representation. Moving or returning a value transfers the caller's cleanup responsibility; every explicit #return is checked for still-live linear locals. Early-return paths must likewise consume the values they own before returning. The compiler never inserts a destructor, so discarding resources with #forget remains an intentional leak rather than hidden cleanup. Generated collections follow the same rule: their generated -free function explicitly destroys each remaining element and releases storage once, and consuming the vector prevents a second free.

#drop also consumes a value and remains useful for explicitly ending a reference's borrow. A value cannot be silently overwritten, abandoned at a scope exit, or consumed on only some control-flow paths. The compiler does not insert destruction calls or silently discard linear values. For a struct, tuple, array, or enum containing references, the borrow checker tracks the provenance of every contained reference. Dropping the aggregate releases each recorded field loan, so all owners become available again only after the aggregate itself is dropped. Code generation does not emit runtime work for references because they are non-owning values.

Operators

Numeric operators are never unqualified in canonical syntax. The operand type is part of the identifier, and integer arithmetic must also specify its overflow mode:

(#u64::add-wrap left right)
(#i32::sub-saturate left right)
(#u128::mul-wrap left right)
(#u128::div-wrap dividend divisor)
(#u128::rem-wrap dividend divisor)

The available integer arithmetic operations are add, sub, mul, div, and rem. The modes are:

  • -wrap: modular two's-complement or unsigned wrapping behavior;
  • -saturate: clamp to the representable bounds.

There is no plain integer arithmetic spelling. #u64::add and #u128::div are rejected because they omit the overflow mode.

Floating-point arithmetic uses the type-qualified operator without an overflow mode:

(#f64::add left right)
(#f32::div numerator denominator)
(#f64::rem left right)

The remaining type-qualified operator families are bitwise operations (&, |, ^, !, <<, >>), comparisons (<, <=, >, >=, ==, !=), and boolean short-circuit operations (#bool::and, #bool::or). The operand type must match the qualifier. Shifts are checked against the width of the left operand when the count is statically known; invalid dynamic counts trap at runtime.

Unary negation is written, for example, as #i128::sub-wrap value.

All conversions are explicit with #as:

(#as value #u64)

Conversions cover integer, character, boolean, and floating-point scalar representations subject to the type checker’s range rules.

Conditionals and blocks

An #if without an else branch must have unit type. Value-producing conditionals require both branches:

(#return (#if (#u64::gt value 0u64)
              value
              0u64))

#block permits statements in an expression position. Its final expression is its value; a block used only for side effects has unit type. Using #break, #continue, #return or another statement directly in an expression produces a diagnostic pointing to that keyword and suggesting #block. Integer arithmetic without a mode reports its public operation name and suggests -wrap/-saturate or a typed infix header such as [#u64 #wrap; ...].

Loops

Statement loops use #break without a value:

(#while (#u64::lt i 10u64)
  (#set i (#u64::add-wrap i 1u64)))

A loop expression has a value only when a reachable break supplies one:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let result #u64: #loop (#break 42u64);
    #return result;
}

An async #while-let may evaluate a synchronous scrutinee and suspend only inside its matched body. The scrutinee is evaluated once per iteration; a failed pattern does not start the body task. Payload values and references needed after suspension are carried by the generated frame and retain normal borrow checks. examples/async_while_let_body.lim demonstrates two Pending iterations followed by Ready(42), without allocating a dynamic task.

The explicit #for form is:

(#for (#let-mut i #u64 0u64)
      (#u64::lt i 10u64)
      (#set i (#u64::add-wrap i 1u64))
  (#set total (#u64::add-wrap total i)))

Inside #generate #async-fn, a unit-returning await can be the step itself:

(#for () keep-going
      (#await () StepTask StepPoll.StepPending StepPoll.StepReady step-poll step-task)
  (#set keep-going false))

The step starts after the body and after #continue, but is skipped by #break and a false condition. A Pending step resumes before the next condition check. Direct body declarations remain in scope through the step, including across a Pending step. That iteration's scope ends after the step, or on a break/return; it does not extend through the next condition. Linear body values still require explicit consumption, and references cannot escape their referents' iteration scope. The condition may itself await. The explicit () result type makes this an effect-only step; no user-maintained dummy binding is required. Generated code contains an ordinary unit assignment, and still undergoes normal type, ownership, and borrow checking. See examples/async_for_unit_step.lim for a runnable Pending/Ready example that exits with status 42.

An awaited condition can also be combined with a computed step, such as arithmetic around an awaited value. Step operands are evaluated in source order and are not reevaluated when a child reports Pending. Changes to captured mutable values, including writes through explicitly borrowed places, are returned by the generated iteration task. Terminal #continue runs the step; terminal #break and #return skip it. See examples/async_for_computed_step.lim for a runnable example.

A synchronous condition can also use an effect-only computed step, including a #call with an awaited argument. For example:

(#for () (#u64::lt index 2u64)
  (#call advance
    ((next (#await #u64 StepTask StepPoll.StepPending StepPoll.StepReady step-poll step-task))
     (counter (#borrow-mut index))))
  ())

Operands before the await execute once, including their side effects. An exclusive reference captured by the iteration is transferred into its child, not duplicated in the parent's Pending state. The source owner remains borrowed until Ready or explicit cancellation consumes the task. Conditional and matched #continue execute the step; #break and #return skip it. examples/async_for_effect_step.lim demonstrates Pending, Ready, an initially false condition, and a break. These forms do not yet imply support for arbitrary control transfers in async bodies.

Conditional early #continue, #break, and #return can precede later awaits inside an iteration. The compiler keeps the remaining statements only on fall-through paths, so skipped work is not evaluated or polled. Scoped branch locals and match payloads remain unavailable after the branch; shadowing and explicit consumption checks still apply. An early #continue in #for runs the step before reevaluating the condition. examples/async_early_continue.lim shows a first iteration skipping its body await and a later iteration resuming that await before returning.

An awaited #while condition may itself await a task-producing dependency. The dependency and condition run in order on each iteration, including the final false condition. Child construction finishes before live captures are saved, and Pending retries do not repeat construction side effects. Conditional helpers return mutable updates with their logical result; linear updated owners belong to the child until Ready restores them. See examples/async_condition_dependencies.lim, which exits 43: three condition constructions add one each, the first body is skipped by #continue, and the second body adds 40 after suspension.

Likewise, a #while-let scrutinee can await a factory and then poll the task that factory returns. Both awaits remain inside the iteration. A successful pattern makes its explicitly typed payload available to the body, including body helpers that suspend again; a mismatch skips every body await. Shared references in those payloads retain their source loans while the frame is Pending. Consuming the cancelled frame releases those loans. The native examples/async_while_let_dependencies.lim exercises repeated conditions, two body suspension points, and construction side effects (exit 40).

Tuple and array patterns, including aliases and nested aggregate patterns, also obtain their captured field types from the declared layout. A suspended match body may retain a shared-reference field without losing its source loan. Ready helpers destructure mutable outputs into typed bindings before assigning them back. See examples/async_pattern_payloads.lim for a tuple-payload match whose bias is retained across a child await (exit 42).

#for-range is shorthand with a typed binding, start, and end. Its bounds are explicit and the range is half-open. Start is evaluated first, then end; both are evaluated exactly once before iteration, including when either bound awaits a child. Changing a variable used by a bound inside the body does not change the captured endpoint. #continue and #continue-to do not evaluate the bounds again. By contrast, #for evaluates its condition on each iteration. See examples/range_bounds_once.lim and examples/async_range_bounds_once.lim for side effects and suspended bounds:

(#for-range (i #u64) 0u64 10u64
  (#set total (#u64::add-wrap total i)))

examples/print_numbers.lim uses the surface syntax to print 1 through 10, one number per line, with a decimal output helper.

Statement layout also permits nested loops without enclosing parentheses:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let-mut total #u64 0;
    #for-range (number #u64) 1 11:
      #set total [#u64 #wrap; total + number];
    #return total;
}

Labels wrap statement loops with #label, and value-loop breaks can target an outer value loop:

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #return: #label outer (#loop (#break-to outer 42u64));
}

Recursive calls are rejected. Mutual recursion is rejected as well.

Patterns and matching

#match requires exhaustive coverage. Enums require every variant; scalar booleans require both values. Integer literals and inclusive #range patterns are combined to check coverage of the complete scrutinee type, including #u128 and #i128. Patterns may overlap or appear in any order; the first matching arm wins. _ supplies a wildcard. Character matches still require a wildcard. Guarded arms do not contribute unconditional coverage. Every arm must be explicitly introduced with #case. Enum payloads are written as constructor patterns:

(#match value
  (#case (Some payload) payload)
  (#case None 0u64))

Tuple, struct, array, scalar, range, typed-literal, and #or patterns are supported. Guards are placed between the pattern and body, using #when:

(#match value
  (#case (Some payload) (#when (#u64::gt payload 40u64)) payload)
  (#case (Some _) 0u64)
  (#case None 0u64))

No wildcard is needed when integer patterns cover the entire domain. This example tests the inclusive boundary between two ranges:

(#fn classify ((value #u8)) #u64
  (#return (#match value
    (#case (#range 0u8 127u8) 0u64)
    (#case (#range 128u8 255u8) 42u64))))
(#fn main () #u64
  (#assert (#u64::eq (#call classify ((value 127u8))) 0u64))
  (#return (#call classify ((value 128u8)))))

Destructuring uses the same aggregate pattern shapes:

(#let (#tuple left right) (#tuple #u64 #u64) pair)

The pattern syntax is checked against the explicitly declared type; bindings are not inferred. When the matched value is a pinned enum reference, ordinary #case is reserved for the wildcard fallback (#case _ body). Every named variant uses #case-pin or #case-pin-mut, including fieldless variants such as (#case-pin Empty body). The shared form binds a #pin-ref payload, including when the input itself is mutable; the mutable form binds a #pin-ref-mut and therefore requires exclusive input. Payload arms accept only one binder or _. Guards, wildcard defaults, exhaustiveness, and duplicate checks follow the usual match rules. The payload stays in its original stack or heap slot, and returned payload references retain the matched owner’s lifetime. Existing unsafe #pin-write and checked #pin-set-field rules still apply inside an exclusive arm.

Ordinary references use #case-ref and #case-ref-mut to borrow enum payloads without pinning the owner. The shared form binds #ref Payload; the exclusive form binds #ref-mut Payload and requires mutable input. Each named variant, including fieldless variants, uses the matching form. #case _ is the fallback, and borrowed and pinned forms cannot be mixed in one match. Payload patterns accept one binder or _, without nested destructuring. examples/borrowed_cases.lim is a runnable example.

All five case forms accept a sequence of body expressions, after the optional (#when condition) guard. Multiple expressions lower to one #block in the arm's scope; the last expression supplies its value. This does not introduce implicit function returns or automatic destruction. For example:

(#case (Work::Poll.Pending pending)
  (#forget pending)
  0u64)

This is equivalent to (#case (Work::Pending pending) (#block (#forget pending) 0u64)). A body is required even after a guard.

Async lowering can still conservatively reject an exclusive match receiver returned by another function: its frame retains a conflicting parent reference handle. This is a generator limitation, not a restriction on ordinary functions; async_generator_matches_reference_returned_by_call records the pending case.

(#enum Choice () ((Choice.Full #u64) Choice.Empty Choice.Other))
(#fn main () #u64
  (#let-mut choice Choice (Choice.Full 41u64))
  (#let observed #u64 (#match (#borrow choice)
    (#case-ref (Choice.Full payload) (#deref payload))
    (#case-ref Choice.Empty 0u64)
    (#case _ 0u64)))
  (#let updated #u64 (#match (#borrow-mut choice)
    (#case-ref-mut (Choice.Full payload) (#block (#deref-set payload 42u64) (#deref payload)))
    (#case-ref-mut Choice.Empty 0u64)
    (#case _ 0u64)))
  (#assert (#u64::eq observed 41u64))
  (#return updated))
(#struct Payload () ((value #u64)))
(#enum Choice () ((Choice.Full Payload) Choice.Empty))
(#fn main () #u64
  (#let-mut choice Choice (Choice.Full (#struct-literal Payload ((value 41u64)))))
  (#let pin (#pin-ref-mut Choice) (#pin choice))
  (#let answer #u64 (#match pin
    (#case-pin-mut (Choice.Full payload)
      (#block
        (#pin-set-field payload value 42u64)
        (#get payload value)))
    (#case-pin-mut Choice.Empty 0u64)))
  (#forget pin)
  (#forget choice)
  (#return answer))

Generated declarations

#generate marks a generated declaration. Compiler-provided generators take one list of named (key value) pairs or a record of literal arguments. Keys may be written in any order, but every required key must appear exactly once. User-defined #gn generators retain their own positional literal interface. For example:

#generate #optional { type = #u64; name = Maybe?; }
#generate #result { ok = #u64; error = #u32; name = Result; }

Fixed-array APIs

(#generate #array ((element T) (length N) (name Name))) emits an alias for (#array T N) and ordinary functions. N must be an unsuffixed nonnegative integer literal that fits #usize. The generated functions use the existing named-call syntax:

Function Parameters Result Contract
Name::in-bounds index: #usize #bool Runtime comparison index < N.
Name::prove-in-bounds index: #usize () Requires Name::in-bounds(index); ensures the exact #usize::lt index N claim.
Name::get values: (#ref Name), index: #usize T Requires #usize::lt index N; emitted only for Copy elements.
Name::borrow values: (#ref Name), index: #usize (#ref T) Requires #usize::lt index N.
Name::borrow-mut values: (#ref-mut Name), index: #usize (#ref-mut T) Requires #usize::lt index N. 
#generate #array { element = #u64; length = 4; name = Array4; }

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let values Array4: #array-of 10 42 30 40;
    #let index #usize 1usize;
    #return:
      #if-valid
        (Array4::in-bounds { index = index; })
        (#block
          (Array4::prove-in-bounds { index = index; })
          (Array4::get { values = (#borrow values); index = index; }))
        0u64
}

The validator is an opaque named predicate. The explicit prove-in-bounds call connects its claim to the comparison required by the accessors. Checking the comparison directly with #if-valid supplies that exact claim without the helper. The checker never unfolds a predicate body or infers a different bound. The accessors use #index-proven: production omits the bounds check, while instrumented builds audit the access. Normal borrowing and ownership checks apply, including for linear elements. The generated helper is an ordinary function with the same audited #ensures promise as handwritten helpers. See generated_array.lim for an explicit conversion between two comparison bounds.

Optional and result APIs

(#generate #optional ((type T) (name Name))) always creates an enum with Name.Some and Name.None, plus the free-standing Name::construct constructor. When the enum and its payload are Copy, it also creates:

  • Name::is-some
  • Name::unwrap-or

(#generate #result ((ok Ok) (error Err) (name Name))) always creates an enum with Name.Ok and Name.Err, plus the Name::ok and Name::err constructors. When the enum and both payloads are Copy, it also creates:

  • Name::is-ok;
  • Name::unwrap-or and Name::unwrap-err-or.

The by-value predicate and fallback unwrap helpers discard values on some paths, so they are omitted for linear payloads, exclusive references, and explicitly linear generated enums. No implicit #forget is inserted. Use explicit matching or #let-else error propagation instead. AST expansion and inspectable generated sources use the same Copy policy, whose declaration context is included in the generated-source cache.

Expansion is part of program parsing. Readable generated Lim sources for both built-in and user-defined #generate invocations are stored as hash-named .lim files under .lim/generated/. Serialized expansions and integrity metadata remain in .lim/cache/, so rg 'pattern' .lim/generated searches only Lim code. Their keys include the invocation, compiler version, supported target, loaded imports, cfg values, and a deterministic fingerprint of compiler Rust sources and build logic. User-generator execution also caches raw emitted syntax there using the generator and transitive #gn-fn hashes. Invalid or stale cache entries are ignored and recomputed. The .lim/ directory is build output; deleting it only causes generators to run again. Generated declarations are not methods and do not introduce namespaces. Nested generated expressions are reserved for future generated forms.

Permanent non-goals

Lim intentionally has no closures, function-pointer values, methods or impl blocks, traits, or user-defined interfaces. Functions are named, free-standing declarations; generators create concrete declarations when specialization or operation families are needed. Thread spawning likewise names the worker at compile time rather than passing a callable value. This keeps call targets explicit, preserves whole-program recursion and ownership checks, and avoids implicit dispatch in generated code.

Direct file references and aliases

An explicit file reference has the spelling ./path/file.lim::declaration. The .lim:: delimiter separates the path from the complete declaration name, which may itself contain :: or an enum variant's dot. Paths resolve relative to the source file containing the reference. Canonical file identity and the declaration name identify the target; two files may declare the same name. No library source is copied or rewritten to add prefixes.

Bind a file-local spelling with #alias:

(#alias allocate = ./allocator/lib.lim::allocate)
(#alias Value = ./values.lim::Value)

Calls may use an alias or a direct reference. Named argument labels keep the callee's declared spelling. Aliases preserve type and function identity and cannot shadow declarations, other aliases, or local bindings. Unused aliases are checked too. Cyclic aliases and conflicting imported spellings are errors. There are no wildcard or prefixing import forms. Every dependency is an explicit file reference or alias; #std selects the compiler-provided standard prelude.

Files in the same nearest lib.lim boundary may refer to implementation files. Cross-library references must target lib.lim and select an exported name. The entry point can export aliases to declarations in its implementation files. Exporting a struct alias keeps the representation opaque; exporting an enum alias exposes its variants under the aliased type name.

For an intentional dependency on an implementation detail, wrap the target:

(#alias inspect = (#unstable ./library/internal.lim::inspect))

#unstable bypasses the entry-point and export restrictions for that exact declaration. It does not expose other declarations or struct representations. Selecting an enum type includes that enum's variants, as for an enum export. It does not remove type, borrow, linearity, or unsafe-call checks. Private functions may rely on library invariants, so this escape hatch is a deliberate dependency on an internal contract, not a promise that arbitrary calls are safe.

Generator definitions resolve their own references in their definition file. Explicit @name inputs resolve in the caller's file before interpretation; unmarked generator arguments remain literal syntax. Generated aliases contain resolved file references and retain the validated definition/invocation context. A generator may deliberately expose a declaration it can access by emitting an alias; this grants access to that declaration, never to its struct fields or unrelated private helpers. Forward generated targets are checked after expansion. Generator cache identities include resolved references and loaded dependencies. Fresh declarations belong to their source file. A resolved reference cannot be used to declare a symbol in another file; generators should receive a separate fresh local name for their outputs. See examples/file_access.lim for two same-named functions in different files.

Value representation and native backend

The established backend emits Intel-syntax x86-64 assembly and follows the explicit x86_64-sysv target description. Scalar integer and pointer-sized ABI words use general purpose registers; #f32 and #f64 values use SSE registers. #i128 and #u128 use two machine words.

An experimental aarch64-linux target (aarch64-unknown-linux-gnu) lowers checked bodies directly through a separate A64 instruction encoder and writes static Linux ELF internally. Its inspectable .inst listing contains resolved instruction words and descriptions; no external assembler or linker is used. Scalar integer arguments use AAPCS64 registers and aligned stack arguments. Aggregates use Lim's internal indirect convention, not a foreign aggregate ABI. The target deliberately rejects operations it does not yet implement; it is not equivalent in coverage to x86-64. See AArch64 testing for the supported subset, emulator execution and remaining acceptance matrix. --target selects builtin cfg defaults independently of the host; explicit --cfg values override those defaults regardless of argument order.

Tuples, arrays, structs, and enums remain value types. Small aggregates can be flattened through the native argument and result registers. Larger aggregates use compiler-generated caller storage at the ABI boundary and are copied as value data. Aggregate operations do not implicitly expose their storage addresses or permit layout reinterpretation; raw pointers remain explicit values handled by the unsafe pointer operations described above. Large struct-field and enum-payload projections copy directly into aggregate storage, so the source value does not need to fit in the native value registers. Enum payload reads check the active discriminant before copying. References to local enums retain the stack-layout tag used to distinguish their downward-growing storage from upward-growing static storage.

Zero-sized values such as () and empty structs/arrays occupy no value words. The compiler computes each function’s maximum call depth after type checking. Use lim --stack-usage INPUT to inspect a static upper bound for generated code from main and each thread entry point, including frames, stack temporaries, outgoing arguments, alignment, generated helpers, and the limiting internal call chain. The analysis follows emitted control flow and reports positive stack-growth loops as unbounded. Any reachable external or indirect callee makes the total unknown; the report shows the known generated portion and the unresolved callees. Runtime startup and external-library stack use are excluded, so finite Lim call depth alone is not a guarantee against stack overflow.

The report recognizes local assembly labels and follows both edges of each conditional branch, including early returns and generated thread error paths. It tracks frame-pointer save/restore operations and includes return-address space for external calls in the known portion. Unsupported stack-pointer updates or inconsistent frame-pointer states produce an analysis error instead of a numeric bound. This analysis describes the emitted assembly; it does not measure the operating system's available stack.

Division by zero, invalid dynamic shifts, failed assertions, #panic, and #unreachable lower to runtime traps. Intentional trap examples are kept separate by the repository’s native sweep.

Compiler pipeline

The library exposes these stages:

  1. lex converts source into tokens with byte and line/column spans.
  2. parse builds untyped S-expressions and preserves #generate as Expr::Generate.
  3. parse_program or parse_program lowers declarations and builtin forms into the typed program representation, including generated forms and concrete generator expansions.
  4. check_types validates declarations, expressions, layouts, patterns, calls, constants, mutability, and the acyclic call graph.
  5. generate_assembly emits native x86-64 assembly.

Grammar and builtin semantics

The core grammar is:

program       = { form } ;
form          = atom | list | quote | quasiquote | unquote | splice ;
list          = "(" { form } ")" ;
quote         = "'" form ;
quasiquote    = "`" form ;
unquote       = "," form ;
splice        = ",@" form ;
atom          = symbol | integer | float | character | string | "#generate" ;
symbol        = identifier ;
identifier    = { letter | digit | "_" | "-" | "." | ":" | "@" | "?" | "!" | "+" | "*" | "/" | "<" | ">" | "=" | "&" | "|" | "^" } ;

Whitespace and slash-to-end-of-line comments may occur between tokens. Builtin declaration and statement forms are the #-prefixed forms described in the tables and sections above; arithmetic and comparison forms include their type and overflow mode in the identifier. #let, #let-mut, #borrow, #borrow-mut, #return, #unsafe, #drop, #forget, and #clone define ownership and borrow behavior; #cfg-* is compile-time only; #gn-* is generator-time only; and #generate declarations expand before ordinary parsing, type checking, and borrow checking. Unknown prefixed forms are rejected rather than treated as future keywords.

Typed word-memory loan inputs

A direct #word-view passed to a checked function has physical layout geometry for owned field, tuple, array-index and enum-payload projections. Consuming and restoring those values maps to the selected backing word range rather than an opaque lifetime anchor. This does not establish stored-reference provenance or permit a dereference through an untracked reference. Unknown runtime coordinates, insufficient known slice extents and opaque pointer anchors still cannot supply a physical consumption contract.

Writes by a checked helper through a direct mutable word view also map to the actual backing offsets. They replace reference-slot metadata only with real incoming loans and publish constructor facts from actual typed writes. Mutation footprints use the projected word range, so neighboring cells retain their facts. A projection through a stored reference addresses its external referent, not the numeric word holding the pointer; it uses ordinary reference checking instead of this owned-layout mapping. Unresolved coordinates, opaque anchors, known-short slices and zero-width ownership identities are not strong writes.

#word-write records a value's actual contained-reference loans at their flat word offsets. Reference-bearing #word-read and #word-view recover those loans; numeric bytes and layout types alone never establish reference provenance. Numeric overwrites retire the metadata at the overwritten offsets. These facts exist only during compilation, without runtime occupancy flags.

Typed writes also establish enum constructor facts at the actual backing word offsets. A subsequent read, take or view need not recover reference slots in an inactive variant. Nested payload tags require a known enclosing constructor; facts belong to the specific cell and enum declaration, not merely a numeric discriminant. Zero-filled memory, a numeric tag write, or a layout type alone does not establish a constructor fact. Unknown branches and opaque addresses remain conservative, and raw mutations invalidate known tags.

#word-forget retires loans but leaves bytes and constructor facts unchanged. An occupied cell still needs real reference provenance after retirement; a new typed empty-constructor write can establish an empty cell instead. These rules do not add runtime occupancy bits or branches.

Checked helper summaries keep byte writes separate from loan retirement. A helper may publish an empty constructor, retire that cell's metadata, and forward the unchanged constructor fact to its caller. Metadata-only forwarding does not recreate an occupied cell's references. Later numeric, raw or unknown writes invalidate the constructor promise; branch joins retain only facts true on every returning path. The distinction is preserved in semantic caches.

An ordinary helper can require loans in a borrowed word slice. The compiler infers those entry requirements and checks the actual stored origins at every call, including through forwarding helpers and cached imports. Returning only a scalar does not hide a reference read. All reaching loans must meet the required shared/exclusive, pinned and owning permissions.

Reference slots in enum payloads have conditional entry requirements. A caller may omit such a loan only when an actual constructor fact proves the payload inactive at every reaching address. Unknown tags still require the loan. The same condition applies to the callee's pointee-access effects; it does not fabricate a reference or suppress unrelated effects. Checked forwarding helpers preserve exact physical tag conditions, including static slice offsets.

A tag condition can describe entry storage only if the callee has not changed that tag before reading the cell. Known disjoint writes preserve the condition; tag writes, raw mutations, unknown effects and ambiguous substitutions discard it conservatively. No runtime flags or conditional checks are added by these compile-time contracts.

A checked helper's owned enum result may also contain an optional reference loaded from numeric storage. If every source for that result payload is a concrete local #u64 array cell with no stored loan, the payload cannot be inhabited by that invocation. This is a result-provenance proof, not a constructor fact about the buffer or permission to read it. The call's reader requirements are still checked independently. Unknown addresses, globals, borrowed-reference boundaries and bodyless callees do not establish absence; live source loans continue to restrict the caller after the result is returned. The same proof applies to an optional owning allocation pointer. Proven absent payloads are excluded from unchanged owned-result match paths, so an impossible owning-pin arm does not require a fabricated allocation identity. Occupied or unknown input slots still require their real loans; this does not authorize access to a live pointer's pointee or retire any of its nested references.

Checked forwarding functions propagate a word reader's owning-pointer requirement as an entry obligation. Inferring that obligation does not turn abstract numeric input storage into an allocation. Each actual caller must still supply a primary, non-lifetime owning loan with the required mutability and pinning; ordinary call and return substitution rejects non-owning slots.

Restoring an owning pointer also retains the loans stored in its allocation. These are pointee metadata, not extra words in the backing array. A checked reader exports requirements for both the owning pointer and its retained reference fields, including through forwarding calls. Concrete restoration requires existing pointee loans; neither a layout nor an owner of a different reference-free pointee fabricates them. Mutation of a retained field's referent and release with a live owning-pin view remain borrow errors.

Moving an input owner preserves pointee loans supplied by its checked entry contract, even when those loans are not adjacent slots in the moved value. Allocation contents are initialized from that existing provenance only on first registration. A later clear or replacement remains authoritative and does not re-import stale entry loans. Typed word writes likewise register the actual owner and pointee loans they store; raw bytes alone do not register them.

(#struct RefValue () { value = (#ref #u64); })

#fn read-value {
  #params = { words = (#slice #u64); };
  #returns = #u64;
  #body:
    #let restored RefValue: #unsafe (#word-read RefValue words);
    #let answer #u64: #deref (#get restored value);
    #forget restored;
    #return answer;
}

#fn main {
  #params = {};
  #returns = #u64;
  #body:
    #let seed #u64 42u64;
    #let-mut words (#array #u64 1): #array-repeat 0u64;
    #unsafe:
      #word-write RefValue
        (#borrow-slice-mut words)
        (#struct-literal RefValue { value = (#borrow seed); })
    #let answer #u64: read-value { words = (#borrow-slice words); };
    #forget words;
    #return answer;
}

Removing the typed write, or overwriting its reference word with a number before the call, fails compilation. Inferred inputs are not permission to fabricate a reference. The unsafe implementation still proves capacity, representation validity and ownership conservation. The same input contracts apply to numeric arrays passed by value, including arrays inside structs and tuples. Moving the backing into another local or extracting its array field preserves the required slot's relationship to the caller's real loan. Shared inputs cannot satisfy an exclusive read. A thread capturing such backing retains its input loans until join; checking only the spawn call would not protect the caller while it runs.

Numeric parameter slots are symbolic candidates during contract inference, not evidence that a reference was initialized. Array candidates use one symbolic index rather than enumerating every element. A typed read specializes the requirement to its selected offset; every ordinary call must then supply the actual loan recorded by a typed write. Raw numeric snapshots are not a general mechanism for transporting concealed reference ownership.

Verification notes

Lim now uses local predicate evidence and explicit function contracts. The symbolic execution engine, Boolean circuit/SAT solver, theorem declarations, induction machinery, theorem CLI and bounded symbolic collection models have been removed. Historical mathematical/theorem experiments remain in Git.

The language reference defines the syntax. contracts.lim is executable.

What the compiler verifies

  • A call has evidence for every declared requirement.
  • Successful #if-valid branches grant facts about exactly the checked subjects.
  • Joins retain facts common to every continuing path.
  • Possible writes revoke facts and saved Boolean evidence that depend on them.
  • Structural read/write footprints cross calls; semantic contracts require explicit annotations at every intermediary.
  • Constrained bindings, fields, parameters and results require evidence.
  • Fixed storage constraints must be restored when exclusive loans end. A returned/reborrowed alias carries the same obligation.
  • Specifications name pure Boolean predicates or typed scalar comparisons and type-correct, pure observations. Unsupported analysis fails closed.

It does not prove #ensures, #preserves, or #assume true. These are the explicit trust boundary. Instrumented execution audits function promises over the exercised inputs; tests cannot establish their universal correctness. Requirements and restoration rules remain compiler obligations in production.

Local analysis

src/contracts replaces the former src/proof and src/theorem.rs modules:

  • mod.rs collects explicit clauses and constrained types before erasure.
  • summaries.rs records transitive structural reads, writes and returned reference origins. It never infers semantic contracts.
  • flow.rs tracks subject identities, predicate facts, dependency versions, branch joins, mutable loans and fixed storage obligations.
  • lowering.rs erases ghost forms and optionally emits native contract checks.

Facts are opaque named applications, matched by predicate and argument identity. There is no SAT solving, arithmetic implication discovery, predicate unfolding, symbolic execution of function bodies, or hidden runtime proof object. The rule checker follows ordinary control flow and declared interfaces. Checked function/type metadata is tied to its lowered AST; modifying a parsed program cannot retain contracts for a different body.

Typed scalar comparisons also form exact atomic facts. They carry their operator, scalar type and operand identities; a comparison does not imply a different bound automatically. Explicit helper calls may require one claim and promise another through #ensures, audited in instrumented execution. This is contract-directed code, not a separate proof kernel or tactic engine.

Scalar comparisons can use ordinary named calls, for example (#call #usize::lt ((left index) (right 4usize))). The compiler generates the typed intrinsic signature and lowers it to the same operation and fact identity as (#usize::lt index 4usize). This spelling change introduces no new inference.

#index-proven accepts a reference to a fixed array and a #usize index. Its implicit requirement is exactly (#usize::lt index N) for the array length. Production omits the bounds check; instrumented lowering uses ordinary checked indexing at the access. Named predicates require an explicit helper to establish the comparison claim. index_contracts.lim demonstrates the helper, a constrained index assignment and the proven access. Ordinary #index and dynamic slice operations retain their checks.

#generate #array emits concrete accessors with explicit comparison requirements, a named bounds validator and an explicit prove-in-bounds helper connecting its claim to the required comparison. Copy elements also receive a by-value getter; linear elements use shared or mutable borrows. These are inspectable ordinary functions, checked and instrumented like handwritten code. generated_array.lim demonstrates intrinsic calls, a programmer-written implication helper and a generated getter.

Ordinary functions in programs containing async code retain their original contracts across planning. The completed generated program receives normal evidence checking and instrumentation. Planning uses checked projections and cannot authorize a production proven access.

Writes to a sibling field need not invalidate a predicate that only reads the other field. Unknown aliases, raw memory and opaque effect boundaries use conservative invalidation rather than assuming disjointness. Baseline Lim ownership, initialization and borrow checking remains mandatory.

Runtime behavior

Use lim --check-contracts INPUT ... or --cfg contracts=check for test builds. contracts=test also enables assertions through CompileConfig.

Form Production Instrumented execution
#if-valid Execute the validation branch Same
#requires Check evidence at compile time Also assert on entry
#ensures Trust the declared promise Assert on every normal return
#preserves Preserve incoming evidence conditionally Assert only if initially true
#assume No evaluation No evaluation
#old Identity of entry observation Capture an entry snapshot
#where Same layout as the base type Same layout; boundary contracts audited
#index-proven Require bounds evidence; omit the bounds check Also check the index at the access

An assumption never disables an independent contract assertion. A predicate failure uses Lim's normal panic path. Panic/divergent exits have no normal postcondition obligation.

Deliberate boundaries

The checker matches conjunctions of named predicates. Disjunction does not grant either operand, and an ordinary #if grants no evidence. Equal arithmetic expressions or two predicates with equivalent bodies are not interchangeable. Loops use conservative entry facts; no induction or inferred loop invariant is performed. Unknown aliasing may require explicit validation or a contract.

After an element reference ends, its owner stays unavailable for general use until the fixed invariant is restored. A base-input predicate can observe the owner for validation, or #assume can supply the closing evidence without execution. A mutable reference returned while an invariant is open transfers that pending obligation; the call does not claim the owner is already valid.

Fixed arrays are expanded up to 1024 constrained elements; type traversal has a depth limit of 64. At most 4096 facts and 200,000 local analysis steps are accepted. Individual identities are limited to 16 KiB; cumulative identity and state-snapshot work is limited to 64 MiB of logical analysis data. These work weights are not a measurement of compiler RSS. Exceeding a limit rejects the program without accepting partial evidence.

#old supports snapshot observations rather than mutable reference handles. Dynamic containers should place a named predicate on the whole collection, for example #where (value VecU64) (sorted (&value)), rather than depend on inferred elementwise relationships. Unsupported nested constraint shapes are rejected with a diagnostic; they never silently lose their requirements. Nested constraints in slices, raw pointers, pinned owners, atomic slots, enum payloads and recursive aggregates currently require a predicate on the enclosing value. Constrained global storage is rejected; construct validated values in functions. Constrained reference handles use immutable bindings; #ref-mut still permits mutation of the referent. Mutable parameter bindings cannot appear directly in postconditions; use scalar #old observations or return the value.

Compiler limits

Limits are implementation boundaries, not permission to weaken a proof. The compiler rejects unsupported mandatory analysis rather than choosing a subset of feasible paths. Supplementary scalar specialization may discard its entire result and fall back to conservative ordinary checking; it must not return an incomplete graph as evidence.

Current major bounds:

Stage Bound Failure behavior
S-expression parser 256 nested expressions Source-associated nesting error
Imports 128 active files, 4096 imports, 64 MiB cumulative source Reject the source/import crossing the limit
Generator interpreter 200,000 evaluation steps; 128 nested expansions Reject the invocation with expansion context
Generator output 1,000,000 emitted syntax nodes Reject oversized expansion
Generated cache artifact reads 64 MiB per artifact Refuse invalid/oversized cache input
Borrow call arguments 1024 alternatives; 128 reference-chain links Reject rather than omit possible aliases
Retained operand loans 1,000,000 expression/retained-value relations Reject before retaining an over-budget snapshot; no partial loan proof is accepted
Predicate evidence 4096 facts; 200,000 local analysis steps; 16 KiB per identity; 64 MiB cumulative identity/snapshot work Reject without accepting partial evidence
Constrained types Depth 64; 1024 expanded fixed-array elements Reject unsupported expansion; use a whole-collection predicate
Async initialization 16,384 states per emitted function Reject with state limit, storage width, and a restructuring suggestion
Async initialization facts 16,777,216 retained boolean cells across before/after/identity vectors Reject before adding an over-budget state; report width and configured state limit

The fact-storage bound is separate from state count. A wide frame can exhaust fact storage with relatively few states. Equal retry states reuse existing facts; merely visiting a loop again does not consume another state budget. The storage bound is not a claim about total compiler RSS: source trees, typed graphs, native emission, allocator overhead, and temporary vectors also use RAM.

The async errors explicitly state that no partial proof was used. Reducing live storage or separating independent suspension histories into concrete functions can reduce analysis work. Raising a limit without understanding the state space is not a substitute for a sound proof.

Browser compiler

The playground compiles Lim inside a browser worker. It uses the Rust compiler built for wasm32-unknown-unknown, then emits a second, WebAssembly module for the example. The worker instantiates that module and calls its exported main function. Source is not sent to a server.

The homepage and handbook is a self-contained HTML document with no JavaScript or external resources. Reading it does not download the compiler. The playground loads the compiler artifact only after an action is requested.

Build and serve

The Nix shell includes the Rust WebAssembly standard library, Node and Pandoc. No npm packages, wasm-bindgen, JavaScript frameworks or Rust crates from a registry are required.

Supported browser programs

The backend emits from validated typed bodies. It runs the same type, ownership, borrow and predicate-evidence checks as native compilation. Contract runtime audits are enabled. It does not reinterpret source in JavaScript or bypass the checker when it encounters a feature it cannot emit.

Safe functions and named arguments Yes; written call-site argument evaluation order Yes
Local bindings, mutation, scalar blocks and branches Yes Yes
#while, #for, #for-range, unit loops, #break, #continue Yes Yes
Wrapping integer arithmetic, comparisons, bit operations Yes Yes
Short-circuit Boolean operators Yes Yes
Scalar predicate contracts and runtime audits Yes Yes

#usize and #isize retain their existing 64-bit Lim scalar meaning here; they are not browser linear-memory addresses. Unsigned 64-bit results display without truncation, using JavaScript BigInt at the boundary. Unit displays as (). The native backend remains the route for the full runtime language.

The emitted example module has no memory. Pure examples have no host imports; printing examples import only lim.print_u64 as described below. The backend is intentionally a teaching subset, not a portable implementation of the native standard library, a general-purpose FFI, or a WASI runtime. Unsupported code generation produces an explicit diagnostic. Check only does not require a runnable main.

Print numbers in the browser

Choose Print 1 through 10 in the playground. This example executes compiled loop and call instructions; the host receives each number from the running WebAssembly module. Standard output displays its text separately from the Result panel's main return value.

(#extern-fn #abi-c browser-print-u64 ((value #u64)) ())
#fn main {
  #params = {};
  #returns = ();
  #body:
    #for-range (number #u64) 1 11:
      #unsafe : #unsafe-call browser-print-u64 { value = number; };
    #return ();
}

This is an explicit foreign-function binding. The normal type, ownership, contract and unsafe-call checks still apply. The backend accepts this external name only with the C calling convention, one #u64 argument and unit return. Its module import is exactly lim.print_u64: (i64) -> (). Each invocation writes an unsigned decimal line, including full 64-bit values; it does not return the printed text. A defined Lim function with that name remains an ordinary function. Other foreign imports are rejected. File references and aliases remain unavailable in the single-file playground.

The browser host supplies this binding; the native linker does not supply its symbol. There is no browser implementation of native String printing, arbitrary text buffers, WASI, or general I/O. The guest receives no memory access through this import. Programs downloaded from printing examples need the same explicit host binding when instantiated elsewhere; pure downloads need no imports.

Stdout is limited to 64 KiB per run. Exceeding it traps execution while retaining the output already accepted and the compiled module download. Small outputs stream immediately; larger output is batched. Stop and the worker deadline still terminate execution, and previously displayed output remains visible after a runtime trap or cancellation. Starting another action clears it.

Bounds, cancellation and failure

  • Source input is limited to 32 KiB of UTF-8.
  • Runnable output is limited to 64 reachable functions and 16,384 typed nodes per reachable function. Unused functions are checked but not emitted.
  • The Rust compiler module has an 8 MiB stack and a 256 MiB linear-memory cap. Memory exhaustion, stack overflow or a compiler trap stops that worker.
  • Compilation and example execution run off the page’s main thread. Each action uses a fresh worker, which is terminated when complete, cancelled, or after the 10-second total deadline. Stop can interrupt an infinite example loop.
  • These limits supplement the compiler’s own analysis budgets. No result is accepted by weakening a failed proof or skipping ownership checking.

A runtime trap can come from #panic, #assert, a failed contract audit, division by zero, an invalid shift count or the stdout limit. A compiled module is still available for download when execution traps. A compile diagnostic has the native error code, source position and excerpt. Editing the source does not change an already-running example; rerun it for a new result.

Compiler interface

lim-browser is a small cdylib wrapper over the lim crate. Its exported ABI version is 1. Only the following entry points and compiler linear memory are needed by the host:

Export Meaning
lim_abi_version() -> u32 Returns 1.
lim_input_resize(bytes: u32) -> u32 Resize the compiler-owned input buffer; return its pointer, or zero for an oversized request.
lim_compile(mode: u32) -> u32 Mode 0 compiles; mode 1 checks. Status 0 means emitted module, 1 means successful check, 2 means diagnostic text.
lim_output_ptr() -> u32 Pointer to the current output buffer.
lim_output_len() -> u32 Current output byte count.
lim_return_type() -> u32 After compilation: 0 unit, 1 Boolean, 2 unsigned 64-bit, 3 signed 64-bit.

Write UTF-8 into the input buffer, call lim_compile, then copy the output. A later call or memory growth can invalidate earlier buffer views. The wrapper never dereferences a caller-supplied pointer. Status 0 contains raw Wasm bytes; statuses 1 and 2 contain UTF-8 text. A compiler trap invalidates that worker; create a fresh one instead of resuming it.

Native Rust callers can use lim::wasm::check(source) and lim::wasm::compile(source). compile returns module bytes plus a ReturnType; both functions return regular Diagnostic errors. Neither uses a disk cache.

The engine tests execute emitted modules, check integer boundaries, branches, loop control, short-circuit evaluation, contract evidence and the exact output import signature, and reject unsupported features. The artifact test loads the actual Rust compiler Wasm, compiles the page’s example templates, checks diagnostics and unsigned results, and verifies runtime postcondition and shift traps. Printing tests execute the page's real loop, check full-width unsigned output, retain stdout before traps, and enforce the output bound and batching. The Chromium test also checks stdout and return values independently, output bounds, printed output across the worker deadline and cancellation, mobile layout, browser Find and the manual’s absence of scripts or fetched resources. Its process/thread flags keep headless Chromium within the development runner’s process limit.

src/wasm.rs consumes checked typed_body nodes, rather than adding a second type checker. Extend its explicit supported cases and add execution tests before advertising another feature. Memory-backed values and aggregate layout need a separate design; silently representing references as integers would lose the language’s guarantees.
